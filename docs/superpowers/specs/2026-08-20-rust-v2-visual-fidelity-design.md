# Rust V2 视觉还原与图标系统修复设计

## 1. 状态与目的

本设计已于 2026-08-20 获得方向确认，用于修复 Rust V2 概念界面在真实 Release
窗口中与效果图之间的明显视觉差距。它是
`2026-08-19-rust-v2-concept-ui-design.md` 的视觉精度补充，不改变该规格已经确定的
业务边界、Rust/Slint 契约和删除安全语义。

当前实现已经具备七个导航入口和主要工作区，但实际截图仍表现为：

- 页面内容未稳定顶部对齐，部分页面出现大面积无意义留白；
- 表格、卡片、标签和详情栏的信息密度明显低于效果图；
- 字号、字重、行高和间距没有形成统一的桌面管理工具层级；
- 现有 GPT Image 2 图标在 16–20px 下线条过细、视觉尺寸偏小、重量不一致；
- 应用标题栏仍使用默认程序图标，顶栏也缺少效果图中的菜单和搜索图标；
- 编译和行为测试通过，但缺少可重复的逐页视觉基线，无法证明还原程度。

## 2. 范围和非目标

本轮只修复视觉系统、布局结构、组件密度、图标资产、空状态和视觉验收链。

必须保持：

- `MainWindow` 的现有根属性、模型、回调、参数顺序和整数枚举语义；
- 节点、扫描、分析、分页、预览、审核、删除和设置的真实数据流；
- 图片不生成缩略图、视频按需加载六帧联系表的边界；
- 删除默认进入回收站、永久删除危险提示和既有确认门禁；
- Windows x64、Slint 1.17.1 和当前 Rust workspace；
- 首选窗口 `1440×900`、最小窗口 `1080×700`。

明确不做：

- 不新增后端命令、协议字段、数据库字段或媒体算法；
- 不伪造容量、速度、ETA、版本、日志、删除历史和任务事件；
- 不把视觉预览夹具编入生产程序；
- 不为追求截图相似而破坏可访问名称、真实动作或离屏可达性；
- 不顺带重构与视觉还原无关的 Rust 业务代码。

效果图中缺少真实数据来源的区域使用两种表达：生产界面显示结构完整的禁用态或
空状态；视觉测试使用隔离夹具填充现有模型字段，用于验证密度，不假装产品已经
拥有额外能力。

## 3. 方案选择

采用“设计令牌与公共组件先行，再逐页还原”的方案。

不采用逐页独立临摹，因为它会继续造成不同页面的字号、行高、按钮和空状态相互
不一致；也不采用只修应用壳和图标的方案，因为真实截图已经证明主要差距来自内容
布局和组件密度。

实施顺序固定为：

1. 建立视觉基线和图标验收工具；
2. 统一主题令牌和应用外壳；
3. 统一公共组件；
4. 完成总览与节点；
5. 完成扫描与任务；
6. 完成重复文件与审核删除；
7. 完成设置与诊断；
8. 执行双尺寸视觉回归、行为回归和 Release GUI 验收。

每一阶段都必须形成可独立截图、可独立审核、可回退的提交，不能等全部页面完成后
才第一次比较效果图。

## 4. 全局视觉系统

### 4.1 颜色

沿用现有浅色 Fluent 令牌：

| 用途 | 值 |
|---|---|
| 窗口背景 | `#F8FAFC` |
| 侧栏、卡片、表格 | `#FFFFFF` |
| 悬停背景 | `#F1F5F9` |
| 边框 | `#E5E7EB` |
| 主文字 | `#111827` |
| 次文字 | `#6B7280` |
| 主色 | `#2563EB` |
| 主色浅背景 | `#EFF6FF` |
| 成功 | `#16A34A` |
| 警告 | `#F59E0B` |
| 危险 | `#EF4444` |

颜色调整的重点不是新增色彩，而是统一对比度：正文不得使用过浅灰色；禁用态必须
仍能阅读；选中态只使用主色、浅主色背景和左侧指示线，不能同时叠加多种强调。

### 4.2 字体层级

| 元素 | 字号 | 字重 |
|---|---:|---:|
| 页面标题 | `24px` | `700–750` |
| 详情主标题 | `20px` | `700` |
| 区块标题 | `15–16px` | `650–700` |
| 导航、按钮、正文 | `12–13px` | `450–650` |
| 表头、辅助说明 | `10–11px` | `450–600` |

生产界面不得再使用 `8px` 或 `9px` 承载表格正文、路径、证据或动作语义。`9px`
只允许用于不影响操作的产品脚注；长路径使用 `elide`、换行或详情区，不通过继续
缩小字号解决。

### 4.3 间距和尺寸

- 内容区标准外边距：`20px`；最小窗口允许收缩到 `16px`。
- 页面标题到首个主要内容区：`12–20px`，不得超过 `32px`。
- 页面主要区块间距：`16px`；卡片和同行控件间距：`8–12px`。
- 基础间距只使用 `4 / 8 / 12 / 16 / 20 / 24px`。
- 普通控件高度：`32–36px`；主操作允许 `38px`。
- 表格表头：`32–36px`；普通行：`36–40px`；双行成员行：`44px`。
- 卡片圆角：`8px`；输入框和按钮圆角：`6px`；边框统一 `1px`。
- 状态胶囊高度：`22–24px`。

所有页面内容默认锚定左上角。只有列表主体、详情主体或明确的空状态可以占用剩余
高度；禁止在页面标题和第一组内容之间放置垂直伸展项。

### 4.4 空状态

空状态分为两类：

- 紧凑空状态：用于指标卡、图表卡和局部面板，高度 `120–180px`；
- 工作区空状态：用于没有任务、组或成员的主列表，在剩余区域内居中显示。

两类空状态都必须包含可理解的标题和原因。存在可执行的下一步时显示一个真实动作；
没有动作时不放置装饰按钮。页面不得出现没有标题、原因或边界的整块纯白区域。

## 5. GPT Image 2 图标系统

### 5.1 资产范围

所有应用自有的可见语义图标都通过内置 GPT Image 2 生成，不再混用 Unicode
字符、字体图标和不同来源的图标包。资产至少覆盖：

- 品牌、窗口程序图标；
- 菜单、搜索、刷新；
- 总览、节点、扫描、任务、重复文件、审核删除、设置；
- 浏览、文件夹、添加、移除、过滤、重试、信息提示等真实页面动作。

Windows 标题栏的最小化、最大化和关闭图标，以及 Slint 原生复选框勾选、
ComboBox 箭头和纯状态圆点保持系统或控件原生绘制，不纳入生成资产。

### 5.2 生成约束

所有提示词共享以下固定约束：

- 纯黑单色、透明背景、正视图、无透视；
- Fluent 风格的简洁轮廓，不使用填充插画、阴影、渐变或纹理；
- 以 `20px` 最终显示为目标，源图线宽必须映射为 `1.75–2px`；
- 图形只表达一个语义，不加入装饰性小点和难以缩放的内部细节；
- 同一轮次先生成完整风格样张，再逐个生成最终资产，避免每枚图标独立漂移。

### 5.3 确定性后处理

Image 2 负责生成图形，后处理只负责透明裁剪、几何归一化、缩放和格式导出，不
重新绘制图形。每枚图标必须经过：

1. 检查透明背景和纯色像素；
2. 计算 Alpha 包围盒和 Alpha 质心；
3. 将导航图标可见包围盒归一化到 `17–18px`；
4. 将刷新和行内动作可见包围盒归一化到 `14–15px`；
5. 进行最多 `0.5px` 的光学中心补偿；
6. 保留四周至少 `1px` 安全区，任何像素不得触边；
7. 导出与 Slint `colorize` 兼容的透明 PNG。

验收指标：

- Alpha 几何中心相对容器中心偏差不超过 `0.5px`；
- 同组图标的可见面积差异不超过 `12%`；
- 缩放到实际尺寸后连续轮廓不得断裂或只剩灰色点阵；
- 20px 侧栏截图中，图标必须与文字基线形成稳定的视觉中心。

品牌图标额外导出 `16 / 24 / 32 / 48 / 256px` 尺寸，用于 Slint 窗口图标和
Windows 可执行文件资源。应用不得继续显示默认通用程序图标。

## 6. 应用外壳

### 6.1 固定尺寸

- 左侧导航：`144px`。
- 顶部命令栏：`58px`。
- 底部状态栏：`32px`。
- 标准右侧详情栏：`300px`，允许在 `280–320px` 内响应式调整。

### 6.2 顶部与侧栏关系

效果图顶部左侧是菜单入口，不是当前占用 `58px` 高度的品牌卡。侧栏顶部调整为
与命令栏同高的菜单区，使用 Image 2 菜单图标；产品身份由窗口标题和 Windows
程序图标承担。导航项目从命令栏下方开始，设置固定在侧栏底部。

导航项目保持 `44–46px` 高度，图标容器 `20×20px`，图标与文字间距 `10px`。
选中项使用浅蓝背景、蓝色图标和 `3px` 左侧指示线。未选中图标必须使用足够深的
中性色，不能出现当前设置图标近似点阵的情况。

### 6.3 顶部命令栏

命令栏按从左到右排列：

1. 节点范围；
2. 在线节点摘要；
3. 可伸展空白；
4. 本地搜索；
5. 独立刷新图标按钮。

搜索框内显示 Image 2 搜索图标。刷新使用 `32×32px` 图标按钮和 `16px` 图标，
不再把刷新图标与文字塞入窄按钮。`last-error` 不参与主工具条的宽度竞争；它进入
底部状态栏或邻近页面的紧凑告警条。

### 6.4 底部状态栏

底栏采用三段布局：左侧引擎状态、中间同步摘要、右侧 PostgreSQL 状态。长错误
只显示截断摘要，并通过可访问名称保留完整文本。任何一段都不得把其余状态推离
可视区域。

## 7. 公共组件

在逐页修改前统一以下组件：

- `FluentCard`：统一背景、边框、圆角和内部边距；
- `MetricCard`：标题、数值、图标和说明形成稳定四卡布局；
- `TabStrip`：标签宽度根据文字和左右内边距计算，不固定为 `112px`；
- `StatusPill`：统一高度、语义色和状态圆点；
- `EmptyState`：支持紧凑和工作区两种密度；
- `DetailPanel`：统一标题、分组、动作区和空状态；
- `GroupTable`、`MemberList`：删除 `8–9px` 业务正文，统一表头和行高；
- 按钮：主按钮、次按钮、危险按钮和图标按钮使用同一状态规则；
- 新增轻量的 `SectionHeader`、`FilterBar`、`SearchField` 和 `ProgressBar`，只封装
  视觉职责，不封装业务状态。

公共组件不得直接访问根属性或 Rust 数据；页面负责传入显示值并转发已有回调。

## 8. 页面还原

### 8.1 总览

- 页面标题后立即显示四张指标卡；不允许出现标题与指标卡之间的空白伸展区。
- 节点健康和最近任务使用统一紧凑表格。
- 底部两个统计卡在没有数据时使用紧凑空状态，不绘制伪造图表。
- `nodes` 和 `tasks` 的预览夹具用于截图验证表格密度，生产空模型仍显示真实空态。

### 8.2 节点管理

- 主区使用“节点表 + 右侧详情”布局，详情宽度 `300px`。
- 添加节点表单固定在主表下方，使用单行 IP、端口和添加动作。
- 节点错误使用带标题的紧凑告警块。
- 版本、运行时长、服务明细和存储目录没有后端字段时显示结构化禁用说明，不伪造值。

### 8.3 新建扫描

- 左侧为扫描根、节点、枚举器、强制重算和本地分析入口；右侧为扫描摘要。
- 多根目录、排除目录、最小大小和高级视频选项不得伪装成可用控件；它们只在
  禁用区说明当前版本边界。
- 删除当前多个大面积“功能暂不可用”白板，改为紧凑说明区。

### 8.4 任务中心

- 页面标题、三个状态标签、任务主表连续顶部排列。
- 主表显示真实阶段、进度、状态和取消动作；没有任务时在表体显示工作区空状态。
- 右侧详情显示已有 ID、阶段、进度和计数；不存在的速度、ETA、当前文件和日志
  使用统一禁用说明。
- 等待队列只有在当前模型能表达时显示；否则不绘制伪造队列行。

### 8.5 重复文件

- 四个重复类型标签和来源/节点/运行 ID 过滤栏组成统一顶部工具区。
- 工作区固定为“组列表 / 成员列表 / 详情预览”三栏。
- 标准宽度下组列表约 `360–380px`，详情约 `300px`，成员列表占剩余宽度。
- 每栏都拥有自己的表头和空状态，不能表现为没有语义的整块白板。
- 图片和视频预览继续严格按现有按需数据流加载。

### 8.6 审核删除

- 审核工作台采用组队列、成员复核、决策详情三栏。
- 删除中心采用批次摘要和执行详情双栏；没有批次模型的标签显示明确不可用状态。
- 快捷复核、路径规则和确认动作按职责分组。
- 只有危险动作使用红色；普通说明和空状态不使用危险色扩大焦虑范围。

### 8.7 设置与诊断

- 左侧二级菜单保持 `190px`，右侧为表单卡片。
- 标签列宽、控件高度和说明列对齐；不使用大段概念说明代替控件结构。
- 真正可编辑字段保持双向绑定；没有接口的字段显示禁用控件和短原因。
- 日志与诊断作为独立区块，展示真实状态、路径和最后错误，不伪造日志列表。

## 9. 视觉预览数据和截图

为避免“真实数据为空”掩盖布局缺陷，测试侧提供确定性的纯 UI 预览夹具：

- 3 个节点，覆盖在线、离线和错误状态；
- 运行中、完成和失败任务各一项；
- 每种重复类型至少 1 个组和 2 个成员；
- 审核状态覆盖未决定、保留和删除；
- 所有值只使用现有 `UiNodeRow`、`UiTaskRow`、`UiGroupRow` 和 `UiMemberRow` 字段。

夹具不得进入 `apps/desktop` 的生产启动路径，也不得通过环境探测意外开启。它只
用于离屏视觉测试或专用预览测试入口。

每个视图至少保存：

- `1440×900` 标准窗口截图；
- `1080×700` 最小窗口截图；
- 与对应效果图并排或半透明叠加的人工审核图。

Windows Graphics Capture 不可用时，允许使用已经验证的手动窗口截图路径：激活
Release 窗口，使用 `Alt+PrintScreen` 获取完整窗口位图，再保存 PNG。必须记录
截图尺寸、Release 来源和包哈希；不得用离屏测试图冒充真实 Windows 窗口截图。

## 10. 验收标准

### 10.1 图标

- 所有应用自有可见图标都有 Image 2 来源和语义文件名；
- 不存在 Unicode 字符冒充图标；
- 20px 图标可见包围盒为 `17–18px`，中心偏差不超过 `0.5px`；
- 缩小后轮廓连续、线宽一致、无触边和过量透明边距；
- 标题栏、侧栏和顶栏使用同一品牌与线性风格。

### 10.2 布局

- 标题到首个主要内容区不超过 `32px`；
- 1440×900 下不存在没有标签、说明或动作的大面积纯白区域；
- 1080×700 下主要操作仍可见或可通过对应滚动区域到达；
- 三栏页面保持从左到右的稳定顺序，详情栏不覆盖主列表；
- 顶栏、侧栏和底栏的内容在两个尺寸下均不溢出。

### 10.3 语义和行为

- 所有现有可访问动作名称保持；新增图标按钮必须提供中文 `accessible-label`；
- 页面切换、标签状态、筛选状态和表单值不会因条件组件销毁而丢失；
- 所有既有回调的调用次数、参数和整数语义保持；
- 删除确认、离线动作禁用和预览按需加载行为不变。

### 10.4 验证命令

- `cargo fmt --all -- --check`
- `cargo check -p dedup-desktop-ui -p desktop --locked`
- `cargo clippy -p dedup-desktop-ui -p desktop --all-targets --locked -- -D warnings`
- `cargo test -p dedup-desktop-ui --locked -- --test-threads=1`
- 与 UI 绑定、预览和删除门禁相关的 desktop-core 定向测试
- `scripts/build-release.ps1`
- `scripts/verify-release.ps1 -Package <zip>`

自动化通过不能替代视觉验收。完成声明必须同时包含标准尺寸截图、最小尺寸截图、
Release GUI 截图和发布包 SHA-256。

## 11. 文件职责

预计修改范围限定为：

```text
crates/desktop-ui/ui/
  app.slint                         # 窗口图标、根契约和页面接线
  theme.slint                       # 全局视觉令牌
  assets/icons/*                    # Image 2 图标资产
  layout/app-shell.slint            # 固定外壳
```

## 12. 完成定义

本轮完成必须同时满足：

1. 图标、字号、间距、卡片、表格、详情栏和空状态形成统一视觉系统；
2. 六张效果图对应的全部视图都拥有标准和最小尺寸截图；
3. 当前 Release 截图中的顶部大空白、超小正文、空白工作区和图标点阵问题消失；
4. 所有应用自有可见图标使用 Image 2 资产，窗口图标不再是默认通用图标；
5. 生产界面没有伪造数据，预览夹具与生产入口严格隔离；
6. 现有 Rust/Slint 接口、业务行为、分页、预览和删除安全链保持兼容；
7. 自动化门禁通过，Release 包重新生成并独立验证；
8. 人工逐页对照结论为通过，而不是仅报告“编译成功”或“元素存在”。

本规格获书面确认后，再生成逐任务、逐文件、带测试与提交边界的实施计划。
