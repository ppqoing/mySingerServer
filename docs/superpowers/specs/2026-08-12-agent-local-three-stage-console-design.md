# Agent 本机三筛计算与审核控制台设计

## 背景

计算端当前由 `nodetray.exe` 管理 `agent.exe`、Worker、Everything 和 Helper，主要提供配置及进程状态；完整的扫描派发、去重分析、结果审核和删除流程集中在 Manager，并依赖 PostgreSQL。

本设计将 NodeTray 扩展为 Agent 的本机 Web 控制台。用户在没有 Manager、没有 PostgreSQL 时，也能在当前机器完成扫描、一筛、二筛、三筛、结果审核和受控删除；配置了 PostgreSQL 时，本地计算结果仍异步同步到中心库。跨机器分析继续由 Manager 负责。

## 已确认范围

- NodeTray 界面只管理当前机器，不发现、连接或管理其他机器。
- 本地界面允许直接创建扫描和计算任务。
- 本地支持扫描、三筛去重、结果审核与删除的完整闭环。
- 本地去重严格限制为当前 `machine_id`，不把其他 Agent 的文件加入本地分组。
- Agent 仍接受 Manager 下发的一筛扫描、二筛和三筛计算任务。
- NodeTray 与 Agent 统一通过 TCP Socket 通信，完全取消 Agent 控制命名管道。
- `agent.exe` 是 `agent.db` 的唯一所有者；NodeTray 不直接打开 SQLite。
- 图片不生成或保存缩略图；审核时按需读取原图、在内存中缩放。
- 视频保留一筛所需的缩略图和缩略图 PDQ。
- 配置 PostgreSQL 时，本地计算结果异步同步到 PostgreSQL；PostgreSQL 不可用不能阻止本地工作。
- 文件物理删除成功后，SQLite 与 PostgreSQL 中对应文件均标记为 `deleted`，但 SHA-512、特征、索引关联和审计记录继续保留。
- 发布形态仍为便携 ZIP，不制作安装包。

## 产品与进程边界

### NodeTray

`nodetray.exe` 是本机 Web 控制台和本地进程管理器，负责：

- 启动、停止、重启和可信认领 Agent 与 Helper；Agent 继续负责其 Worker 生命周期；
- 通过 Agent Socket 提交任务、读取状态、审核结果和发起删除；
- 展示本机运行状态、资源统计、任务、三筛结果、错误和配置；
- 按文件 ID 请求受限的本机图片预览。

NodeTray 不打开 `agent.db`，也不在自身进程中执行扫描、分析或删除。

### Agent

`agent.exe` 是本机数据和任务运行时，负责：

- 独占 SQLite 的迁移、读写和任务恢复；
- 接收 NodeTray 本地任务与 Manager 远程任务；
- 调度共享 Worker 池；
- 执行本机一筛候选生成、二筛、三筛和成组；
- 保存本地任务、分析批次、审核和删除结果；
- 通过现有 Agent 到 Helper 的安全链路执行删除；
- 配置 PostgreSQL 时，通过 outbox 同步本地结果。

### Manager

`gui.exe` 继续负责多个 Agent 的连接、跨机器任务派发、跨机器去重、审核和删除。Manager 可以分别向 Agent 下发二筛和三筛特征任务，并汇总不同机器的结果。Manager 不参与 Agent 本地任务的可用性判定。

## Socket 通信设计

### 单一监听器

Agent 使用现有 TCP 监听地址，例如 `0.0.0.0:9101`，同时接受 Manager 与 NodeTray 的并发连接。NodeTray 从 Agent 配置读取端口，并始终连接 `127.0.0.1:<port>`，不连接 `0.0.0.0`，也不写死 9101。

Agent 未启动时没有可连接的 Socket，因此 NodeTray 直接启动 `agent.exe`。Agent 启动后，状态、配置、任务、三筛、预览、审核、删除和优雅停止全部通过 Socket 完成。Socket 优雅停止失败时，NodeTray 才能在核验 PID、启动时间和最终 EXE 路径后强制结束已可信认领的进程。

### 客户端身份与本机权限

Agent 发送现有 `Hello` 后，NodeTray 发送客户端身份握手：

- `role=nodetray`；
- 本地控制令牌；
- 客户端协议版本。

本地控制令牌保存在便携数据目录的受保护文件中，由 Agent 与 NodeTray 首次运行时安全创建或读取。令牌不得出现在命令行、日志、错误摘要或前端状态中。

NodeTray 专属命令必须同时满足：

- TCP 来源是回环地址；
- 客户端角色是 NodeTray；
- 控制令牌恒定时间比较通过。

Manager 保持现有任务协议兼容，但不能调用本机配置、文件预览和生命周期等 NodeTray 专属接口。连接断开不取消已经受理的任务；重连后客户端按任务 ID 恢复查询或订阅。

### 协议能力

Socket 协议增加以下能力：

- 本地任务创建、查询、取消和重试；
- 分阶段分析启动、状态与统计；
- 本地重复组和成员分页查询；
- 审核选择保存与读取；
- 删除预览、一次性确认和执行结果；
- 本机资源与 Worker 状态；
- 按数据库文件 ID 请求图片预览；
- NodeTray 身份的优雅停止。

二筛和三筛计算消息携带任务 ID、阶段、不可变文件身份、所需字段掩码和来源。相同任务 ID 与相同信封可安全重试；相同任务 ID 携带不同参数时拒绝。Agent 在执行前核验路径、SHA-512、大小和修改时间；文件发生变化时返回 `stale`，不复用旧结果。

旧版合并式 `Phase2Task` 继续兼容，解释为同时请求二筛和三筛字段。新版 Manager 分别下发二筛与三筛任务。

## 本地任务模型

本地任务统一记录：

- UUID；
- 类型：扫描、分析、删除；
- 来源：NodeTray 本地或 Manager；
- 阶段：扫描/一筛、二筛、三筛、发布；
- 状态：排队、运行、等待恢复、完成、失败、取消；
- 进度、速度、统计和安全错误摘要；
- 创建、更新和完成时间；
- 不可变任务信封摘要。

Agent 重启后保留全部终态任务；中断的本地任务进入“等待恢复”并自动继续。Manager 派发任务根据原任务 ID 恢复，不能生成重复计算记录。

本地任务与 Manager 任务共享 Worker 池，按“来源 + 阶段”公平轮转。调度器不能让任一来源长期占满 Worker，并必须为控制和状态请求保留响应能力。

## 一筛、二筛、三筛

### 扫描与一筛基础特征

扫描任务默认计算一筛所需的全部基础特征，不提供关闭这些特征的选项。

所有文件默认计算 SHA-512。图片默认计算：

- PDQ-256；
- 图片质量；
- 宽度和高度。

图片不计算、不保存缩略图。视频默认计算：

- 时长；
- 视频缩略图；
- 缩略图 PDQ-256；
- 缩略图质量和尺寸。

新文件、内容变化或特征缺失时必须计算；文件未变化且特征完整时允许复用缓存；“重新扫描”强制重新计算。任一必需特征失败时记录为部分失败，不能把文件标记为一筛就绪。

一筛负责快速候选生成：

- SHA-512 相同的文件直接形成精确重复确认组；
- 图片使用 PDQ 倒排、长宽比、质量和汉明距离筛选；
- 视频使用时长窗口、缩略图 PDQ 和汉明距离筛选。

相似图片和相似视频的一筛结果只是候选，不允许直接删除。

### 二筛

二筛只请求并计算分区 pHash：

- 图片使用 `3×3` 分区 pHash；
- 默认每区汉明距离阈值为 10；
- 默认通过比例至少为 0.80；
- 视频在 6 个均分时间点逐帧执行同一判定。

缺失特征由本机 Worker 按需补算。二筛不通过的候选直接淘汰；二筛通过后才生成三筛任务，避免提前执行无用的 Sobel 计算。

### 三筛

三筛计算结构相似度并作最终确认：

- 图片使用 Sobel 结构直方图，默认余弦相似度至少为 0.85；
- 视频对 6 帧执行 Sobel 比较，至少 4 帧有效；
- 视频平均相似度至少为 0.80，或至少 4 帧通过。

最终判定为“确认重复”“不重复”或“无法确认”。只有 SHA-512 精确重复和三筛“确认重复”的组可以进入删除审核；“无法确认”单独展示原因且禁止直接删除。

### 原子发布

每次本地分析使用独立 generation。在临时 generation 中完成候选、二筛分数、三筛分数和成组后，以单个 SQLite 事务发布为当前结果。任一阶段或发布失败时，上一次完整结果继续可见。

## SQLite 数据模型

在现有文件与特征表之外增加：

- 本地任务及阶段统计；
- 分析批次与 generation；
- 一筛候选对；
- 二筛、三筛分数和最终判定；
- 本地重复组与成员；
- 审核选择；
- 删除批次、文件结果和审计元数据；
- PostgreSQL 同步 outbox。

本地分析查询必须带当前 `machine_id` 条件。本地结果与 Manager 结果以 scope、机器 ID 和分析批次隔离，不能互相覆盖。

## PostgreSQL 同步

配置有效 PostgreSQL DSN 时，Agent 异步同步：

- 本机文件及一筛基础特征；
- 一筛候选结果；
- 二筛分数及通过状态；
- 三筛分数及最终判定；
- 本机精确、图片和视频重复组；
- 本地任务状态及阶段统计；
- 已确认审核决定；
- 删除完成后的文件状态和删除结果。

尚未提交的界面勾选只保存在本机。同步使用 SQLite outbox，按机器 ID、分析批次和任务 ID 幂等写入。PostgreSQL 不可访问时，本地任务继续运行，outbox 持续保留并后台重试；连接恢复后自动补传，不需要重新计算。

本地分组标记为 `scope=local`，不能覆盖 Manager 的跨机器分组。Manager 可以消费已同步的特征和分阶段分数，继续执行跨机器分析。

## 审核与图片预览

审核页面按精确、图片、视频分类，支持路径、文件名、大小和审核状态筛选。每组默认不选择删除文件；用户必须明确指定保留文件和待删除文件。

图片预览请求只携带本地数据库文件 ID。Agent 必须验证该行属于当前机器、未删除且当前文件身份匹配，然后按需读取原图并在内存中缩放返回。预览不生成磁盘缩略图，也不接受客户端传入任意文件路径。视频使用扫描阶段已经生成的缩略图。

## 删除与数据保留

删除必须经过：

1. 已确认重复组中的审核选择；
2. 删除预览，展示数量、总大小和完整路径；
3. 一次性确认令牌；
4. Agent 到 Helper 的现有安全删除链路；
5. 每文件结果落库和审计。

默认使用软删除；永久删除属于高级操作并要求额外确认。执行前再次核验文件大小、修改时间和 SHA-512。文件变化、未经审核或判定为“无法确认”时拒绝删除。

只有 Helper 明确报告物理删除成功时，Agent 才在同一 SQLite 事务中：

- 将对应 `files.status` 标记为 `deleted`；
- 保留 `sha512`、一筛/二筛/三筛特征和哈希索引关联；
- 保留重复组历史、审核决定和删除审计；
- 写入 PostgreSQL 同步 outbox。

PostgreSQL 同步只把对应文件状态更新为 `deleted`，不得清空 SHA-512、删除特征行或级联删除历史分数。正常分组和候选查询排除 `deleted` 文件，但历史和审计查询仍可关联原哈希。

删除失败或结果不确定时不得标记为 `deleted`。软删除文件恢复到原路径后，下次扫描重新核验并激活该文件记录。

## 页面设计

### 本机概览

- Agent、Worker、Everything 和 Helper 状态；
- CPU、内存、磁盘读取速度和待处理文件数；
- 当前任务、最近错误和组件生命周期操作。

### 本地任务

- 通过目录选择器添加一个或多个根目录；
- 创建“扫描并计算一筛特征”或“扫描后自动执行三筛分析”；
- 重新扫描、扩展名过滤、取消和重试；
- 显示来源、阶段、状态、进度、速度、失败数和耗时。

### 去重分析

- 独立启动本机分析；
- 展示一筛、二筛、三筛和发布阶段；
- 展示每阶段输入、淘汰、通过、错误和耗时；
- 同一时间只发布一个本地分析 generation。

### 结果审核

- 精确重复、相似图片、相似视频和无法确认四类视图；
- 展示一筛、二筛、三筛分数；
- 按需图片预览及视频缩略图；
- 明确保留文件和待删除文件。

### 删除确认与记录

- 删除预览、软删除和高级永久删除；
- 每文件成功、失败和不确定状态；
- 可追溯的本地及已同步审计记录。

### 本机配置

- Everything、Worker 数量、内存、超时、扫描扩展名和视频缩略图缓存；
- 一筛、二筛、三筛阈值；
- Agent Socket 监听地址；
- 折叠的 PostgreSQL 同步配置。

界面不显示其他 Agent 或机器连接列表。PostgreSQL 配置错误不影响界面和本地计算。

## 错误与隐私

- 前端只展示稳定错误码和安全摘要，详细错误写入本地日志；
- 不在日志、Socket 错误或诊断内容中泄露密码、DSN、控制令牌或未经授权的完整路径；
- 图片预览和任务查询必须分页并设置响应大小上限；
- Socket 写入采用单连接串行发送，避免帧交错；
- Agent 或 NodeTray 重启后，未消费的删除确认令牌失效。

## 测试策略

实现遵循 TDD，至少覆盖：

- 没有 PostgreSQL 和 Manager 时完成扫描、三筛、审核和软删除；
- 扫描默认生成全部一筛特征，图片目录中不产生缩略图文件；
- 二筛不通过时不生成三筛任务；
- Manager 分别下发二筛和三筛任务并收到正确结果；
- 旧合并 `Phase2Task` 兼容；
- NodeTray 与 Manager 并发连接、任务公平调度和重连恢复；
- Agent 重启恢复本地任务和最后完整分析 generation；
- 分析或发布失败不破坏旧结果；
- 错误角色、错误令牌和非回环来源无法调用 NodeTray 专属命令；
- 图片预览不落盘、不接受任意路径并拒绝 stale 文件；
- 删除前身份变化、删除失败和不确定结果不修改文件状态；
- 删除成功后 SQLite 与 PostgreSQL 标记 `deleted`，同时保留 SHA-512、特征和索引；
- PostgreSQL 离线时 outbox 保留，恢复后幂等补传；
- 本地 scope 不覆盖跨机器分组；
- Compute 便携包合同仍只包含运行所需 EXE、配置模板、数据目录和依赖。

## 验收标准

- 用户只启动 Compute 包即可在本机完成扫描、三筛、审核和删除闭环。
- NodeTray 不直接访问 SQLite，所有业务操作均经 Agent Socket。
- PostgreSQL 和 Manager 离线不阻断本地工作；配置 PostgreSQL 后结果最终一致同步。
- Manager 能向同一 Agent 分阶段下发二筛和三筛任务。
- 图片不生成缩略图，审核预览不落盘。
- 只有明确成功删除的文件被标记为 `deleted`，且本地与中心库保留全部哈希索引数据。
- 三筛阶段、分数、错误、任务来源和同步状态均可在本机界面观察。
