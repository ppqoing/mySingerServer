# Rust V2 瞬态任务文件与最近分析结果设计

## 1. 目标

本次调整将计算任务、本地分析和删除运行态从节点 SQLite 中移出，解决基础缓存阶段虽然已经使用批量 `SELECT`，却仍被逐文件任务事务拖慢的问题。

最终数据所有权固定为：

- SQLite 只保存文件、内容、媒体特征、文件故障和中心同步事实。
- 计算任务使用按物理盘拆分的瞬态 UTF-8 TSV 文件，并在内存维护当前运行状态。
- 本地分析只保留最近一次成功结果的 UTF-8 TSV 文件。
- 删除计划、进度和历史均不持久化。
- Node 重启后不恢复计算、分析或删除进度；重新发起任务即可得到正确结果。

任务文件和分析结果禁止使用 JSON，也不生成持久化 `.idx` 文件。

## 2. 方案选择

采用“保留缓存 SQLite，运行态转为瞬态文件和内存”的方案：

- 保留当前 schema 3，避免现有文件和媒体特征缓存全部失效。
- 旧任务、分析和删除表在启动时清空，后续不再写入。
- 不创建新的任务数据库或临时分析数据库。
- 不删除现有表，等以后确有必要升级不兼容 schema 时再物理移除。

未采用的方案：

- 直接升级 schema 并删除表会迫使现有节点重建全部媒体缓存。
- 使用临时 SQLite 保存运行态仍会产生事务、WAL 和写锁，不符合降低缓存阶段写入的目标。
- JSONL 解析成本和字段分派高于固定列 TSV，不用于任务或分析结果。

## 3. SQLite 数据边界

SQLite 继续保存：

- `metadata`：产品 schema 和文件库 revision。
- `contents`、`files`：内容键、媒体类型、文件路径和当前有效状态。
- `image_stage1`、`image_stage2`、`video_metadata`、`video_frame_stage1`、`video_frame_stage2`：媒体特征缓存。
- `contact_sheets`：联系表相对路径。
- `file_faults`：磁盘读取故障和 Worker 崩溃事实。
- `sync_outbox`、`sync_state`：PostgreSQL 增量同步事实。

SQLite 不再保存：

- 计算任务、任务项、扫描根和任务阶段。
- 本地分析运行、阶段、输入、候选、分组、成员和复核决定。
- 删除批次、删除项和删除墓碑历史。

启动时在一个事务中清空旧运行态表。清理不得删除 `contents`、`files`、特征、故障、联系表或同步数据。

删除成功后仍需更新 `files.active=0` 并写文件状态同步事件。这是当前文件事实，不是删除历史。

## 4. 基础缓存查询

### 4.1 查询阶段只读

枚举完成后形成当前进程内的稳定清单和固定总数。每批最多 1,000 项，直接调用现有 SQLite 批量缓存接口：

```text
机器 ID + 规范路径 + 文件大小
    -> files
    -> contents
    -> 图片/视频特征与联系表
```

查询前禁止：

- 创建任务项。
- 更新任务或阶段。
- 打开逐文件事务。
- 把文件状态改为 queued/running。

批量查询的 SQL 数量必须与批次大小无关。正常 1,000 项路径批次继续使用固定数量的业务 `SELECT`。

### 4.2 完整性分类

查询结果不是简单的命中布尔值，而是每个文件的有效字段和缺失字段掩码。

以下情况视为缺失：

- `NULL`、空字段或数据库约束之外的长度。
- 非法或零尺寸的媒体元数据。
- `base_complete=false`。
- 缺少规定的视频槽位或槽位字段。
- 显式计算失败状态或历史失败占位符。
- 缺失、损坏或与内容键不匹配的联系表。

合法的全零特征不能仅凭数值判断为默认占位符。纯色图像可能产生合法零值，完整性必须由显式状态、字段长度和结构规则共同判断。

后续不再把 Worker 失败写成特征占位符。失败只写 `file_faults`，对应字段保持缺失，使下一次新任务可以重试。

缺失字段使用稳定数值掩码表达，至少覆盖：

- MD5。
- 媒体探测和媒体元数据。
- 图片一筛、图片二筛。
- 视频元数据。
- 视频一筛槽位 0～5。
- 视频二筛槽位 0～5。
- 联系表。

完整缓存命中项不生成任务记录。部分命中项只计算掩码指定的字段，不重复计算已有有效字段。

## 5. 按物理盘拆分的任务文件

### 5.1 文件布局

每次计算创建独立运行目录：

```text
data/node/runtime/<run-id>/
  PhysicalDisk7-hdd.tasks.tsv
  PhysicalDisk8-ssd.tasks.tsv
  PhysicalDisk5+12-unknown.tasks.tsv
```

任务文件统一位于 Node 数据目录，不写入媒体根。文件名中的物理盘身份只表达任务归属。

路径在枚举边界已经绑定物理盘编号和类型。缓存查询后，只有需要计算的项才写入对应物理盘任务文件。

### 5.2 固定行格式

任务文件使用 UTF-8、无 BOM、制表符分隔和固定列顺序。每行只表示一个需要计算的文件：

```text
状态\t任务项ID\t工作类型\t规范路径\t显示路径\t文件大小\t已知MD5\t缺失字段掩码
```

- `P`：待计算或正在计算。
- `C`：所需结果已经成功提交 SQLite。
- `F`：本轮文件计算失败。

状态是每行第一个固定单字节。任务文件管理器在追加时记录行偏移，SQLite 提交成功后只把 `P` 原位修改为 `C`；文件级失败修改为 `F`，不重写整行。

Windows 文件名不能包含制表符或换行，路径字段无需 JSON 转义。所有非路径枚举、ID、整数、MD5 和掩码均使用固定 ASCII 表达。

### 5.3 文件是实际调度来源

任务文件不是日志副本，而是当前运行的调度来源：

1. 缓存查询生产者按批向各物理盘文件追加任务并刷新可见边界。
2. 每个物理盘读取器顺序读取自己文件的下一批 `P` 项，只保留有限预读窗口。
3. 统一磁盘调度器根据配置中的 SSD/HDD/unknown 每盘额度和全局额度选择 lane。
4. 全局额度不足时按配置权重轮转，并保留老化保护，避免低权重 HDD 饥饿。
5. 缓存生产者完成后封闭所有任务文件；所有记录进入 `C/F` 后本轮计算终止。

同一个 `TransientTaskFileSet` 独占文件句柄、追加游标、读取游标和状态偏移，其他组件只通过明确命令访问，避免并发 seek/write 破坏行边界。

## 6. Worker 与 SQLite 提交

调度给 Worker 的身份包含 run ID、任务项 ID、物理盘身份、任务文件行偏移和缺失字段掩码。Node 必须核对同一身份后才能接受结果。

执行顺序固定为：

1. Worker 只计算掩码要求的字段。
2. Node 校验媒体类型、固定长度、有限浮点值、视频槽位和内容键。
3. NodeStore 在事务中合并新增结果，不用缺失或失败值覆盖已有有效缓存。
4. 必要时写入或更新 `contents`、特征表、`files`、`file_faults` 和同步 outbox。
5. SQLite 事务提交成功并返回 ACK 后，任务文件状态才从 `P` 改为 `C`。
6. Worker 或单文件读取失败时状态改为 `F`，其他物理盘继续调度。

Node、Worker 或 SQLite 在 ACK 前退出时，任务行最多保持 `P`。运行目录会在下次启动清空并由新缓存查询重新生成，因此不会把未提交结果误判为完成。

## 7. 扫描收尾与正确性

缓存命中项虽然不写任务文件，但仍加入当前进程内的本轮已见路径集合。只有以下条件同时满足才能收尾：

- 全部缓存批次查询完成。
- 所有物理盘任务文件已经封闭。
- 所有任务行进入 `C/F`。
- 所有 SQLite 结果 ACK 已返回。

收尾事务批量写入新增或变化的文件关系，并按扫描根和路径组件失效本轮未出现的旧活动位置，同时写同步 outbox。

枚举失败、任务取消、任务级基础设施错误或进程退出不得调用收尾事务，因此不会错误失效旧文件。单文件 `F` 计入本轮失败，但不阻塞其他文件和任务终态。

成功收尾时递增 SQLite `metadata` 中的文件库 revision。该 revision 只表示分析输入可见的文件集合发生变化，不因普通运行时进度更新而变化。

## 8. 运行任务与协议

`RuntimeTaskRegistry` 是当前进程任务、阶段、进度、Worker 和最近失败的唯一事实源。任务中心和总览页不得从 TSV 或旧 SQLite 任务表重建第二份状态。

Task ID、Analysis ID 和删除批次 ID 仍通过现有协议暴露，但只在当前 Node 进程有效：

- 当前进程内已完成计算任务仍可被本地分析选择。
- 任务完成时的 outbox 高水位保存在内存任务快照。
- Node 重启后旧 ID 返回任务不存在，Desktop 清除对应运行状态。
- 重启不自动重建或继续旧任务，用户重新发起扫描、分析或删除。

`data/node/runtime` 在启动时按精确目录边界清空。清理不得扩大到 Node 数据目录、缓存目录、媒体根或生产目录。

## 9. 最近一次本地分析结果

### 9.1 生命周期

本地分析运行状态、冻结输入、候选、分组和复核决定只存在当前进程内存及当前 `.partial.tsv`：

```text
data/node/results/latest-analysis.partial.tsv
data/node/results/latest-analysis.result.tsv
```

- 启动时删除 `.partial.tsv`。
- 分析失败或取消时删除 `.partial.tsv`。
- 新分析运行期间继续保留并允许查看上一份成功结果。
- 新分析成功后原子替换 `.result.tsv`。
- 任意时刻只保留最近一次成功结果。

### 9.2 结果格式

结果使用版本化 UTF-8 TSV。头记录包含格式版本、分析 ID、文件库 revision、分析模式、阈值和创建时间。每个最终组成员占一行，并重复保存查看所需的组信息，避免读取时再做关联查询：

```text
记录类型\t分组类型\t分组ID\t是否代表\t代表MD5\t代表大小\t机器ID\t规范路径\t显示路径\tMD5\t文件大小\t一筛分数\tpHash通过块数\t二筛分数
```

尾记录保存数据行数和前面字节的 SHA-256。完成发布顺序为：

1. 写完数据和尾记录。
2. 刷新并关闭文件句柄。
3. 使用 Windows 原子替换语义替换旧 `.result.tsv`。
4. 替换成功后才向 UI 发布新结果。

发布前失败不得影响旧成功结果。

### 9.3 滑动窗口读取

结果查看不使用分页和持久索引：

- UI 只持有当前可见行及前后预读窗口。
- 后台顺序扫描 TSV，校验格式、行数和 SHA-256，但不把全部结果对象加载进内存。
- 已经扫描到的行偏移只保存在当前进程内存。
- 向后滚动超过窗口时使用内存偏移重新读取。
- 跳到尚未扫描的位置时，后台继续顺序扫描到目标位置并显示加载状态。
- 重启后首次打开重新扫描，不生成 `.idx`。

结果头的文件库 revision 与当前 SQLite revision 不一致时，结果仍可只读查看，但必须明确标记“数据已变化”，并禁止从该结果直接执行删除。

## 10. 删除边界

删除计划、复核选择、进度和每项结果只存在内存，不写 SQLite 删除表或文本历史文件。

创建删除计划时必须验证分析结果 revision 仍是当前 revision，并在内存冻结本批次。随后每个文件执行前必须重新验证：

- `LocationKey` 当前活动。
- 实际文件大小仍匹配。
- 流式 MD5 仍匹配结果中的内容键。

删除成功后立即更新 `files.active=0`、递增文件库 revision 并写文件状态同步 outbox。删除失败只更新当前内存详情和普通进程日志。

任一成功删除都会递增 revision，并使当前分析结果变为过期。revision 变化不撤销已经冻结的同一内存删除计划，该计划仍按逐文件路径、大小和 MD5 校验继续处理；新的删除计划必须等待重新分析。进程退出后不恢复剩余项，用户重新扫描和分析。

## 11. 错误处理

- 缓存批量查询失败时不生成该批任务行，也不返回部分分类结果。
- 任务文件批量追加或刷新失败属于任务级基础设施错误，停止本轮且不执行扫描收尾。
- 非法任务行、重复任务项身份或行偏移不匹配立即停止本轮，不能调度猜测数据。
- SQLite ACK 失败时任务行保持 `P`，不能提前标记 `C`。
- Worker 返回未请求字段时拒绝该项，不能覆盖缓存。
- 分析结果格式、行数或校验值错误时拒绝展示并要求重新分析。
- 运行目录清理只允许作用于已解析的 `data/node/runtime` 和精确 `.partial.tsv`。

## 12. TDD 与验收

实现必须使用真实行为测试，不使用读取源码文本判断是否修改。

### 12.1 SQLite 和缓存分类

- 1,000 条缓存查询通过 SQL trace 证明只有固定批量 `SELECT`，查询前无任务 `INSERT/UPDATE`。
- 完整图片、完整视频、普通文件、部分字段、空字段、非法尺寸、失败占位和缺槽视频分别得到准确缺失掩码。
- 合法全零特征保持命中。
- Worker 部分结果只补缺失字段，不覆盖已有有效字段。

### 12.2 任务文件与调度

- 缓存完整命中不生成任务行。
- 部分命中只写请求掩码。
- 两个物理盘生成两个独立任务文件。
- 调度器真实从任务文件顺序读取，并保持配置权重、全局额度和老化保护。
- SQLite 提交失败时状态保持 `P`；成功 ACK 后改为 `C`；文件失败改为 `F`。
- Worker 崩溃只结束对应行，其他磁盘继续运行。
- 重启清空运行目录并重新查询缓存生成任务。

### 12.3 分析和删除

- 启动清除 `.partial.tsv`，保留 `.result.tsv`。
- 新分析失败或取消不覆盖旧成功结果。
- 新分析成功只保留最近一次结果，并通过原子替换和校验。
- 滑动窗口不会把全部结果对象载入内存，也不创建 `.idx`。
- revision 不匹配时结果只读且删除入口禁用。
- 删除过程不写删除表；成功后 `files.active=0`、revision 和 outbox 正确更新。

### 12.4 回归和真实媒体

- node-store、node-engine、protocol、desktop-core 和 desktop-ui 相关行为测试全部通过。
- `cargo fmt --all -- --check` 与 `git diff --check` 通过。
- 使用真实媒体执行完整扫描，记录缓存查询吞吐、任务文件生成、Worker CPU、各物理盘 I/O 和最终结果。
- 再次运行相同媒体时，完整缓存命中项不得进入任务文件。
- 测试通过前不打包、不替换 `I:\Tool`。

## 13. 完成标准

满足以下条件才算完成：

1. 基础缓存查询阶段不再创建或更新 SQLite 任务记录。
2. 只有真正缺少计算数据的文件进入对应物理盘任务文件。
3. Worker 只计算缺失字段，SQLite ACK 后任务行才标记完成。
4. 任务文件成为实际调度来源，并保持当前按物理盘加权与老化保护语义。
5. Node 重启清空全部运行态，不恢复旧计算、分析或删除任务。
6. SQLite 只保留长期缓存、故障和同步事实。
7. 本地分析只保留最近一次成功 TSV，失败结果不能覆盖它。
8. UI 使用滑动窗口动态加载，不分页、不使用 JSON、不生成 `.idx`。
9. 删除不保存历史，仍通过重新验证、文件状态和 outbox 保证当前结果正确。
10. 行为测试、回归测试和真实媒体验收均无新增失败。
