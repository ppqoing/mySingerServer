# Manager 降级启动与保存后自动重启设计

## 背景

当前 `gui.exe` 在绑定管理界面的 HTTP 监听端口之前，会先加载完整配置、连接 PostgreSQL、恢复数据库任务并初始化 Agent 连接。PostgreSQL 不可访问、认证失败或 Agent 离线时，进程会直接退出，用户无法进入已经存在的“GUI 设置”页面修改配置。

本设计把“打开管理界面”和“外部运行依赖可用”分开。除本地监听地址无法绑定外，PostgreSQL 与 Agent 的错误都不能阻止界面启动。用户保存配置后不做复杂的进程内热切换，而是自动重启 `gui.exe`，让全部运行组件从同一份新配置重新建立。

## 目标

- 没有 `gui.json` 时自动创建默认配置，并支持直接双击 `gui.exe` 打开界面。
- 默认监听地址为 `127.0.0.1:18081`。
- PostgreSQL 或 Agent 不可用时，Manager 仍打开界面并允许编辑配置。
- 保存有效配置后自动重启 Manager，使 PostgreSQL、Agent 和业务参数统一生效。
- 监听地址改变时，新进程使用新地址，页面能够转到新地址并等待服务恢复。
- 连接错误对用户可理解，同时不泄露密码、完整 DSN 或敏感本地路径。

## 非目标

- 不处理已存在但 JSON 损坏或字段非法的 `gui.json`；此类情况继续启动失败。
- 不实现 PostgreSQL、Agent 或任务服务的进程内热切换。
- 不安装、启动或管理 PostgreSQL。
- 不改变 Manager 便携包“连接用户已有 PostgreSQL”的定位。
- 不要求通过 `Start-Manager.ps1` 启动；直接双击 `gui.exe` 必须具备完整能力。

## 首次启动配置

启动时先解析 EXE 最终路径和 `-config` 参数，得到唯一的配置文件路径。若该文件不存在，程序使用以下部署默认值创建一份完整、可被现有配置校验器接受的 `gui.json`：

- `listen_addr`: `127.0.0.1:18081`
- `pg_dsn`: `postgres://dedup@127.0.0.1:5432/dedup`
- `agents`: `[{"addr":"127.0.0.1:9101"}]`
- 其余字段沿用 `DefaultGUI` 中的心跳、一筛和二筛默认值。

文件必须使用 UTF-8 无 BOM、规范 JSON、原子替换和仅当前用户可读写的权限策略。并发启动时只允许一个进程发布首次配置；另一个进程应读取已经发布的完整文件，不能覆盖用户内容。

若配置已经存在，则严格读取并校验。损坏配置不会被自动覆盖或备份。

## 启动顺序

启动流程调整为以下顺序：

1. 解析运行路径，创建日志目录并初始化日志。
2. 创建或严格读取 `gui.json`。
3. 初始化始终可用的配置服务和运行状态服务。
4. 绑定 `listen_addr`，成功后立即启动 HTTP 服务并打开浏览器。
5. 后台尝试连接 PostgreSQL并构建完整业务运行时。
6. PostgreSQL 成功后恢复扫描任务、二筛任务、删除服务和分析服务。
7. 独立启动 Agent 连接池；Agent 离线只更新状态，不终止 Manager。

监听地址无效或端口被占用仍属于启动失败，因为没有可供用户操作的界面。PostgreSQL 创建、连接、认证、任务恢复或 Agent 连接失败均进入降级状态，不能关闭 HTTP 服务。

## 降级运行时

HTTP 路由分为两类：

- 始终可用：静态页面、`GET /api/config`、`PUT /api/config`、运行状态和重启状态。
- 依赖业务运行时：扫描、分组、分析、删除、任务和数据库统计等接口。

业务运行时未就绪时，依赖接口返回 HTTP 503 和稳定错误码 `database_unavailable`，不能 panic、无限等待或返回底层连接错误。Agent 状态接口仍可返回配置的 Agent 地址，并标记为离线或尚未连接。

运行状态至少包含：

- PostgreSQL：`connecting`、`connected` 或 `error`；
- Agent：每个地址的连接状态；
- 最近一次启动错误的安全摘要；
- 当前运行配置与磁盘配置是否一致；
- 是否正在重启及预期恢复 URL。

配置页面应在显著位置显示外部依赖状态。底层错误经过稳定映射，仅显示例如“PostgreSQL 认证失败”“PostgreSQL 地址不可达”“Agent 未连接”，日志和 HTTP 响应都不得包含密码或完整 DSN。

## 保存与自动重启

`PUT /api/config` 继续执行完整字段校验并原子保存。语义相同的配置不触发重启；配置发生变化时执行以下协议：

1. 服务原子写入并重新读取验证 `gui.json`。
2. 根据新 `listen_addr` 计算恢复 URL。
3. HTTP 响应返回 `saved=true`、`restarting=true` 和恢复 URL。
4. 响应发送完成后，父进程使用当前 `gui.exe` 的最终路径启动重启子进程，并传递同一绝对 `-config` 路径。
5. 子进程通过内部参数等待指定父进程真正退出，不能提前抢占旧监听端口。
6. 父进程停止接收新业务请求，取消后台任务，等待当前请求在有界超时内结束，然后关闭监听器和数据库/Agent 资源。
7. 子进程确认父进程退出后，按正常启动流程读取新配置并绑定端口。
8. 前端显示“正在重启”，轮询恢复 URL；服务恢复后刷新页面。若监听地址发生变化，则导航到新 URL。

内部重启参数不写入 `gui.json`，也不改变用户从资源管理器直接双击 `gui.exe` 的入口。`-no-browser` 和显式 `-config` 语义在重启时必须保持；由已打开页面负责等待恢复，因此自动重启子进程不再次弹出浏览器。

如果新配置中的 PostgreSQL 或 Agent 仍不可用，新进程必须以降级模式打开界面。只有新监听地址无效或被占用时，新进程无法提供界面；父页面的轮询最终应显示“重启后监听失败，请检查日志”，而不是永久显示加载状态。

## 并发与生命周期

- 同一时刻只允许一个配置保存触发重启；后续保存请求返回稳定的 `restart_in_progress`。
- 自动重启只能启动发布目录中的同一个 `gui.exe` 最终文件对象，不能从当前工作目录或 `PATH` 查找程序。
- 关闭顺序必须先停止接收新请求，再取消后台工作，最后关闭数据库和 Agent 连接。
- 等待父进程使用进程句柄或等价的操作系统同步机制，不使用固定睡眠时间判断端口释放。
- 重启启动失败必须写入固定便携日志目录，但不得删除或回滚已经成功保存的配置。

## 界面行为

首次打开时仍默认进入总览。若业务运行时未就绪，总览展示可操作的降级提示，并提供“打开 GUI 设置”入口；不能把整个页面替换成通用错误页。

GUI 设置页继续编辑完整配置。保存成功后按钮进入禁用状态，页面显示“配置已保存，Manager 正在自动重启”。前端停止发起普通业务请求，仅轮询恢复端点。重启成功后刷新；超时后保留新地址、日志位置和手动重新打开提示。

## 测试策略

实现必须遵循测试驱动开发，至少覆盖：

- 配置不存在时先失败测试，再验证自动创建的完整默认配置和权限。
- PostgreSQL 拒绝连接或认证失败时，HTTP 监听器仍成功绑定，配置接口可读写。
- 数据库依赖接口在降级状态返回 503 `database_unavailable`。
- Agent 离线不影响启动，并能在状态接口中观察。
- 配置保存响应完成后才开始关闭服务器。
- 自动重启复用最终 EXE 路径、绝对配置路径和 `-no-browser` 语义。
- 子进程等待父进程退出后才绑定端口，不依赖固定延时。
- 监听地址改变时前端轮询新 URL；不变时轮询当前 URL。
- 重启中禁止重复保存；重启失败不会破坏已保存配置。
- 日志、HTTP 错误和 UI 消息均不包含测试密码或完整 DSN。
- Manager 便携包合同仍只包含 `gui.exe`、配置模板、中文说明和启动脚本；首次自动生成的 `gui.json` 不回写发布 ZIP。

## 验收标准

在一个没有 `gui.json`、PostgreSQL 未启动且 Agent 离线的新解压目录中直接双击 `gui.exe`，应自动生成配置并打开 `http://127.0.0.1:18081/`。用户可进入 GUI 设置修改 PostgreSQL 与 Agent，保存后看到自动重启过程。新进程无论外部依赖是否连接成功都应重新提供界面；依赖可用时业务页面恢复工作，不可用时显示明确的降级状态。只有监听端口无法绑定可以阻止界面启动。
