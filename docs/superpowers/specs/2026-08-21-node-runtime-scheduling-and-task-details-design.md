# Rust V2 Node 资源调度、远程配置与任务阶段详情设计

## 1. 状态与目的

本设计于 2026-08-21 经用户逐项确认，用于补齐 Rust V2 当前实现中的四类真实缺口：

- 任务中心只能显示一个笼统阶段和总计数，无法展示各阶段、各 Worker 和当前文件；
- Node 虽然可以启动多个 Worker，但扫描链仍按“派发一项、等待一项”的方式串行推进；
- 设置页只能保存管理端 PostgreSQL、重连、删除模式和算法阈值，不能读取或修改远程 Node 配置；
- 文件读取、坏盘疑似故障、Worker 崩溃、视频联系表缓存和磁盘空间不足缺少统一运行边界。

目标是在不伪造数据、不迁移用户旧数据、不永久保存运行详情的前提下，实现：

1. 从设置页按机器唯一 ID 加载 Node 配置；
2. 由 Node 校验、原子保存配置并自行重启；
3. 按本机物理磁盘类型和总并发配置文件读取；
4. 让多个 Worker 真正同时计算不同文件；
5. 在任务中心每 2 秒展示全部任务类型的阶段、进度、Worker 和失败详情；
6. 对读取超时和 Worker 崩溃文件进行可追溯记录；
7. 复用以 MD5 分目录保存的视频六帧联系表；
8. 仅在操作系统报告磁盘空间不足时，清理全部符合条件的运行时可再生文件；
9. 最终以只读真实媒体执行一次持续 30 分钟的计算验收。

## 2. 当前实现证据

当前协议的 `TaskSummary` 只包含任务类型、状态、总项数、完成数、失败数、跳过数和
Outbox 高水位；`TaskEvent` 虽有单一 `stage` 字符串，但任务列表映射仍固定显示
“节点任务”。SQLite `tasks` 表只保存任务总计数，`task_items` 只为单项保存一个阶段
字符串，没有阶段列表、阶段进度或 Worker 运行快照。

当前 `ScanEngine::run_existing` 在路径循环中同步执行 MD5，再调用
`WorkerPoolStage1Processor::process`。该处理器派发一项后立即等待 `next_event`，因此
即使 WorkerPool 已启动多个进程，扫描链也只能保持一个一筛请求在途。

当前 `NodeConfig` 只有监听 IP、端口、Worker 数和枚举器；`AppLayout` 从可执行文件
固定推导数据、配置、日志和缓存路径。设置页中的四类路径只是只读显示，不参与
`SaveSettings`。

本设计不把这些缺口隐藏在 Slint 假数据中，而是从协议、Node 配置、调度器、运行态
遥测和真实 UI 绑定一起补齐。

## 3. 方案选择

采用“Node 资源调度器 + 内存任务遥测 + 远程配置快照”的方案。

不采用直接把全部阶段字段塞入现有 `TaskSummary` 的最小补丁，因为任务列表会被
Worker 和文件级详情持续放大，也不能解决现有扫描串行等待问题。

不采用独立任务服务和永久事件日志，因为用户已经明确要求 Node 重启后清除任务
详情；为此引入独立服务和长期事件存储既增加复杂度，也违反产品边界。

核心结构如下：

```text
Desktop 设置页
  ├─ GetNodeConfig ────────────────> Node 配置服务
  └─ SaveNodeConfigAndRestart ─────> 原子保存 → Node 自重启

Desktop 任务中心
  ├─ 本地 RuntimeTaskRegistry
  └─ 每 2 秒查询各 Node RuntimeTaskRegistry

Node 扫描流水线
  枚举 → 缓存查询 → 物理磁盘读取/MD5 → 多 Worker 计算 → 单写入队列
                         │                    │
                         └──── 运行遥测 ──────┘
```

## 4. 范围与非目标

### 4.1 本轮范围

- Node 配置远程加载、保存并自重启；
- Node 路径、读取和 Worker 参数；
- 本机物理磁盘识别、分盘队列和总读取并发；
- 扫描、一筛、二筛等 Worker 请求的多项在途调度；
- 扫描、本地分析、跨机器分析、删除、同步的统一临时任务详情；
- 文件故障数据库和日志；
- 视频六帧联系表的 MD5 路径与复用；
- 磁盘已满时清理运行目录内全部符合条件的可再生文件；
- 设置页、任务中心和日志诊断页的真实数据绑定；
- 相关自动化验证和最终真实媒体半小时计算测试。

### 4.2 明确不做

- 不为 Node 配置管理增加鉴权、加密或管理密钥；继续使用现有可信局域网明文模型；
- 不支持 UNC、网络映射盘和其他远程文件系统；
- 不自动迁移旧数据库、旧日志、旧缓存或旧配置；
- 不永久保存任务阶段、速度、当前文件和 Worker 详情；
- 不重试造成 Worker 进程崩溃的文件；
- 不启用 Worker 崩溃次数熔断；
- 不把读取超时表述成已经确认的硬盘物理损坏；
- 不删除真实媒体、源码、Cargo `target`、发布包、数据库、配置、日志或运行文件；
- 不运行与本轮改动无关的全量测试。

## 5. Node 配置模型

### 5.1 配置字段

Node 配置扩展为以下分组。

基础配置：

- 监听 IP；
- 监听端口；
- 默认枚举器，默认 `Everything`。

路径配置：

- 数据路径；
- 实际配置文件路径；
- 日志路径；
- 缓存路径。

读取配置：

- 每块 HDD 的读取线程数，默认 1；
- 每块 SSD 的读取线程数，默认 2；
- 未识别本地物理磁盘的读取线程数，默认 1；
- 全部物理磁盘的总读取线程数；
- 读取块大小，默认 4 MiB；
- 单块读取超时，默认 3 秒；
- 单块读取重试次数，默认 2 次，即最多尝试 3 次。

Worker 配置：

- 自动或手动模式；
- 自动模式保留的逻辑核心数，默认 1；
- 手动模式 Worker 进程数；
- 自动模式的有效 Worker 数为“可用逻辑核心数减保留核心数”，且最少为 1。

所有计数必须有明确上限并在 Node 唯一配置边界验证；界面输入不能绕过 Node 校验。

### 5.2 路径语义

- 相对路径统一以 `node.exe` 所在目录为基准；
- 绝对盘符路径和本机卷挂载路径允许使用；
- 相对路径在配置响应中原样返回，不替换为绝对路径；
- Node 只在校验、创建目录和实际访问时内部解析；
- 当前工作目录永远不参与路径解析；
- UNC、网络映射盘和其他远程文件系统在保存时拒绝；
- 路径变化后只创建并使用新目录，不移动或删除旧目录；
- 数据路径变化后使用新位置的数据库，设置页必须明确警告旧数据库不会迁移。

### 5.3 配置路径的引导文件

为了允许“配置文件路径”配置自身，在 `node.exe` 固定运行目录保留一个不可移动的
轻量 `bootstrap.toml`。它只记录实际 Node 配置文件的原始路径字符串。

修改配置路径时按以下顺序执行：

1. 解析并校验目标路径；
2. 在目标位置写入完整新配置的临时文件；
3. 刷新并原子替换目标配置；
4. 写入并原子替换 `bootstrap.toml`；
5. 任何一步失败时继续使用旧引导和旧配置，不重启；
6. 成功后保留旧配置文件，不做自动迁移或删除。

## 6. 配置协议与 Node 自重启

协议新增：

- `GetNodeConfig`；
- `NodeConfigSnapshot`；
- `SaveNodeConfigAndRestart`；
- `NodeRestartAccepted`。

`NodeConfigSnapshot` 至少包含机器唯一 ID、配置原始字段、配置版本摘要、检测到的逻辑
核心数和当前有效 Worker 数。配置版本使用当前配置文件内容摘要；保存命令必须携带
加载时获得的摘要，摘要不一致时返回冲突并要求重新加载。

设置页只有两个真实动作：

- “加载配置”；
- “保存并重启”。

Node 收到保存命令后：

1. 校验机器状态、配置版本和全部字段；
2. 验证目标路径均为本机物理磁盘路径；
3. 原子写入配置和必要的引导文件；
4. 启动新的 `node.exe --wait-for-parent <PID>`；
5. 只有新进程创建成功后才返回 `NodeRestartAccepted`；
6. 响应完成后当前 Node 停止接收新工作并退出；
7. 新进程等待旧进程退出，再打开数据库、WorkerPool 和监听端口；
8. 管理端按机器唯一 ID 等待重连，重连后自动重新加载配置确认生效。

如果新进程创建失败，旧 Node 保持运行并返回失败。保存失败、版本冲突或字段校验失败
都不得触发重启。

## 7. 物理磁盘调度器

### 7.1 磁盘识别

Node 在访问文件前通过 Windows 卷和存储设备 API 将路径映射到本机物理磁盘编号，
并查询 HDD、SSD 或未知本地设备类型。

- 不同物理磁盘拥有独立读取队列；
- 相同物理磁盘上的不同盘符或挂载点进入同一队列；
- 跨多个物理区段的卷视为一个复合设备，使用保守的未知设备并发；
- 无法映射到本机物理磁盘的路径拒绝扫描；
- 网络驱动器即使表现为盘符也按远程路径拒绝。

### 7.2 许可和公平性

调度器同时实施两层许可：

1. 每块物理磁盘按类型限制在途读取数；
2. 全局限制所有磁盘合计在途读取数。

调度使用分盘公平轮转，避免一个大目录长期占满总读取线程。MD5 读取、项目自身的
媒体读取以及 Worker 处理期间的文件访问都必须持有对应磁盘许可；Worker 不能绕过
Node 的磁盘限流。

同一机械硬盘默认只允许一个文件级读取，但用户可以在 Node 设置中提高该值。SSD
默认允许两个文件级读取。总并发仍受总读取线程数约束。

## 8. 有界扫描与计算流水线

扫描链改为：

```text
文件枚举
  → 路径规范化和批量缓存查询
  → 按物理磁盘排队
  → 分块读取和增量 MD5
  → 内容复用判断
  → 多 Worker 媒体探测/一筛或二筛
  → 单 SQLite 写入队列
  → 成功收尾
```

各队列均为有界通道，容量由读取线程数和 Worker 数推导，不开放无上限积压。上游在
下游饱和时等待，避免枚举数百万文件后把全部路径和结果同时留在内存。

读取采用配置块大小进行流式处理，不一次读入完整文件。项目自身控制的读取使用该
块大小；FFmpeg 内部仍使用其自身缓冲，但 Worker 处理整个文件期间持有物理磁盘
许可，因此不会突破文件级并发限制。

WorkerPool 必须允许多个请求同时在途：

- 最多占用当前有效 Worker 数；
- 每个 Worker 同时只处理一个文件；
- 结果允许乱序返回；
- 通过任务 ID 和任务项 ID 在内存调度边界精确关联；
- SQLite 结果写入保持单写者；
- 取消任务后停止新派发，取消等待项并终止该任务正在占用的 Worker。

## 9. 读取超时、重试与文件故障

### 9.1 可取消读取

Node 控制的块读取使用 Windows 可取消异步 I/O。单块超过 3 秒时取消该次读取，短暂
退避后重试同一块，最多重试 2 次。任意一次重试成功则继续文件，不写文件故障记录。

三次尝试全部失败时：

- 跳过整个文件；
- 标记为“疑似物理读取故障”，不得表述为已确认物理损坏；
- 写入运行日志；
- 写入持久文件故障数据库；
- 继续处理其他文件。

后续扫描仍允许重新读取该文件；如果读取和计算成功，则清除该文件对应的旧故障
记录。

### 9.2 Worker 崩溃

Worker 进程崩溃时：

- 当前文件立即标记失败并跳过；
- 当前任务项绝不自动重新排队；
- 写入运行日志和文件故障数据库；
- 重建对应 Worker 槽位；
- 后续继续处理下一个文件；
- 不按次数熔断整个任务。

Node 重启恢复时，已经因 Worker 崩溃标记失败的任务项也不得再次执行，避免相同坏
文件造成无限崩溃循环。

### 9.3 文件故障表

文件故障记录是持久诊断数据，不属于会随 Node 重启清除的任务详情。记录只包含：

- 机器唯一 ID；
- 文件规范路径和显示路径；
- 文件大小；
- 故障类型；
- 发生阶段；
- 可选 Windows 错误码；
- 简短错误说明。

明确不记录任务 ID、任务项 ID、块偏移、块大小、Worker PID、退出码、首次或最近
发生时间、重复次数。唯一键按机器唯一 ID、规范路径和故障类型约束；重新发生时只
替换当前错误摘要，不累计次数。

协议提供 `ListFileFaults` 和 `ClearFileFault`，供设置页“日志与诊断”分页查看和手工
清除。

## 10. 临时任务遥测

### 10.1 生命周期

每个 Node 和 Desktop 都有进程内 `RuntimeTaskRegistry`。运行详情不写 SQLite：

- Node 重启后清空 Node 运行任务、阶段、速度、当前文件和最近失败；
- Desktop 重启后清空跨机器分析和同步的运行详情；
- 已完成任务不从 SQLite 恢复到任务中心；
- SQLite 仍保留活动任务异常恢复所需的最小状态；
- 若重启发现未完成任务，创建新的“恢复任务”，从“恢复与校验”阶段重新展示，不
  恢复旧阶段历史。

任务中心每 2 秒 Tick 一次：刷新紧凑任务列表，并只为当前选中任务获取完整详情。
完成、失败、取消、节点断线和重连事件立即刷新，不等待下一个 Tick。

### 10.2 任务与阶段模型

运行任务摘要包含：

- 任务 ID、类型和所属机器唯一 ID；
- 当前状态和运行阶段摘要；
- 总体完成数、总数、失败数、跳过数；
- 总体进度。

完整详情包含：

- 全部阶段；
- 当前 Worker 工作项；
- 最近 20 条运行失败。

每个阶段包含：

- 稳定阶段 ID、用户可读名称；
- 等待、运行、完成、失败或跳过状态；
- 文件、字节、候选对、节点或删除项等进度单位；
- 已完成数、总数、失败数和跳过数；
- 总数未知时的不确定进度；
- 当前速度、已运行时间和预计剩余时间。

流水线允许多个阶段同时为“运行中”。任务列表使用“枚举 / 读取 / 一筛并行”等摘要，
不能强行把并行流水线压成虚假的单一阶段。

当前 Worker 详情包含 Worker PID 或槽位、阶段、当前文件路径、所属物理磁盘、已处理
文件数和速度。这些字段只在内存存在。

### 10.3 任务类型和阶段

扫描任务：

1. 准备；
2. 枚举；
3. 缓存查询；
4. 读取与 MD5；
5. 媒体探测与一筛；
6. 持久化与收尾。

本地分析：

1. 冻结输入；
2. 加载特征；
3. 一筛候选；
4. 补齐二筛；
5. 聚类；
6. 保存结果。

跨机器分析：

1. 收集节点输入；
2. 冻结输入；
3. 一筛；
4. 分发二筛；
5. 等待节点；
6. 二筛判定；
7. 聚类与保存。

删除执行：

1. 复验选择；
2. 按节点分发；
3. 回收站或永久删除；
4. 汇总结果。

同步任务：

1. 拉取变更；
2. 写入 PostgreSQL；
3. 确认高水位；
4. 清理 Outbox。

协议新增 `ListRuntimeTasks`、`GetRuntimeTaskDetails`、`RuntimeTaskSummary`、
`RuntimeTaskDetails`、`RuntimeStageDetails` 和 `RuntimeWorkerDetails`。现有
`TaskSummary` 继续服务恢复和分析门禁，不承载临时详情。

## 11. 视频六帧联系表缓存

视频联系表使用内容 MD5 的小写十六进制字符串存储：

```text
<Node 缓存路径>/contact-sheets/<MD5 前两位>/<完整 32 位 MD5>.jpg
```

例如：

```text
cache/contact-sheets/a1/a1b2c3d4e5f60123456789abcdef0000.jpg
```

处理规则：

- 在获得文件 MD5 后计算目标路径；
- 如果目标文件已经存在，直接复用，不再合成六帧联系表或编码 JPEG；
- 即使用户选择强制重新计算，也只重算缺失或要求重算的媒体特征，不覆盖已有 JPG；
- 如果数据库缺少联系表相对路径但文件存在，则修复数据库路径；
- 媒体特征缺失时仍执行必要探测和特征计算，只跳过联系表生成；
- 新联系表先写临时文件，再原子替换目标文件；
- 数据库只保存相对于 Node 缓存路径的相对路径；
- 旧的 `content_id.jpg` 不迁移、不自动删除。

## 12. 磁盘空间不足清理

自动清理只在 Windows 实际返回磁盘空间不足错误时触发，不做后台周期检查，也不
配置容量阈值。

清理范围必须同时满足：

1. 位于发生空间不足的同一物理磁盘；
2. 位于 `mySingerServer` 运行安装根内；
3. 由程序明确登记为可再生运行时文件；
4. 当前没有被任务、预览或写入租约占用。

符合条件的文件包括：

- 失去任务归属的 `.tmp`、`.partial` 中间文件；
- Node 和 Desktop 的运行时预览缓存；
- 视频联系表和缩略图；
- 其他有明确再生成路径的派生产物。

明确排除：

- 真实媒体和扫描根；
- SQLite 数据库和文件故障记录；
- 配置和 `bootstrap.toml`；
- 日志；
- `node.exe`、`worker.exe`、FFmpeg、Everything 等运行文件；
- 源码、Cargo `target`、发布目录和发布 ZIP。

一次空间不足清理按以下规则执行：

1. 冻结当前可清理文件集合；
2. 删除集合内全部符合条件的文件，不以“已释放足够空间”为提前停止条件；
3. 对仍被数据库引用的联系表，在同一受控流程中清除数据库相对路径；
4. 记录清理文件数和释放字节数；
5. 完整清理结束后只重试原写入一次；
6. 重试仍然空间不足时返回明确错误，不再触发第二轮清理。

设置页只显示最近一次自动清理结果，不提供容量阈值设置。

## 13. 设置页设计

Node 配置放在“节点服务”分区。顶部提供节点选择框，显示机器唯一 ID、节点名称、
地址和在线状态；节点离线时禁止加载和保存。

加载成功后显示：

1. 基本配置：监听 IP、端口、默认枚举器和只读机器唯一 ID；
2. 路径配置：数据、配置、日志和缓存路径，并提示相对路径基于 `node.exe`；
3. 磁盘读取：HDD、SSD、未知本地盘每盘线程，总线程，块大小，3 秒超时和 2 次重试；
4. Worker：自动/手动模式、保留核心、手动 Worker 数、检测核心和预计有效 Worker 数。

唯一保存动作是“保存并重启”。加载前、内容未变化时或节点离线时禁用。点击后显示：

```text
校验 → 保存 → Node 重启 → 等待重连 → 验证配置
```

版本冲突要求重新加载。路径变化时显示旧数据不迁移警告。配置值均由 Node 返回和
校验，Desktop 不直接读写远程文件。

“日志与诊断”新增文件故障分页列表和最近一次空间不足清理摘要。

## 14. 任务中心设计

任务中心采用双栏：

- 左栏约 35%，显示紧凑任务列表、类型、机器唯一 ID、状态和总体进度；
- 右栏约 65%，显示完整阶段、Worker 和失败详情；
- 在 1080px 最小窗口下仍保留双栏，左栏使用自身滚动，不覆盖右侧详情。

右侧详情从上到下显示：

1. 任务标题、类型、机器唯一 ID、状态和总体进度；
2. 全部阶段纵向列表，每阶段显示状态、完成/总数、速度、耗时和 ETA；
3. 当前 Worker 表格；
4. 最近 20 条运行失败。

任务详情刷新失败时保留最后一次画面并标记“数据已过期”，不能把旧快照伪装成实时
状态。Node 断线时立即更新状态。

## 15. 错误与恢复语义

- 配置校验、写入或引导更新失败：不重启；
- 新 Node 进程创建失败：旧 Node 保持运行；
- 重连超时：设置页显示“已保存，Node 尚未恢复连接”；
- 单文件读取或计算失败：记录并跳过，不终止其他文件；
- Worker 崩溃：当前项失败、不重试，槽位重建；
- 磁盘空间不足：清理全部符合条件文件后重试一次；
- SQLite 写入失败：停止相关任务，不能把未提交结果显示为完成；
- 运行遥测丢失：不影响 SQLite 恢复门禁；
- Node 重启：清除旧运行详情，未完成持久任务以新恢复任务重新展示。

## 16. 兼容与迁移

- 协议版本必须提升，Desktop 与 Node 必须成套更新；
- 旧 NodeConfig 通过 `serde(default)` 获得新增字段默认值；
- 首次启动没有 `bootstrap.toml` 时继续从旧固定位置读取配置，并创建引导文件；
- 新增 `file_faults` SQLite schema 迁移；
- 不迁移旧路径中的数据库、日志、缓存和配置；
- 不迁移或删除旧 `content_id.jpg`；
- 不把临时任务详情写入任何现有任务表。

## 17. 验证策略

### 17.1 开发期间

只运行与本轮改动直接相关的测试，不运行额外全量工作区测试。必须覆盖：

- Node 配置加载、内容摘要冲突、原子保存和自重启；
- 相对路径原样往返、绝对路径、本机物理盘和网络路径拒绝；
- HDD/SSD/未知盘每盘并发、总线程上限和公平轮转；
- 配置块大小、3 秒读取超时、2 次重试、重试成功和故障入库；
- 文件后续成功时清除旧故障；
- 多 Worker 同时在途、乱序结果、取消、崩溃跳过和槽位重建；
- Worker 崩溃项在恢复时不再执行；
- 2 秒 Tick、并行阶段统计、终态立即刷新和 Node 重启清空；
- 全部五类任务的阶段映射；
- 设置页加载配置、保存并重启和版本冲突；
- 任务中心阶段、Worker、最近失败和数据过期状态；
- MD5 联系表路径、已存在文件复用、强制重算仍复用和数据库路径修复；
- 注入磁盘已满错误后清理全部符合条件文件、保护活动文件和只重试一次。

磁盘已满测试必须使用故障注入或隔离临时目录，不允许真实填满用户磁盘。Worker 崩溃
测试使用隔离媒体夹具，不使用用户真实媒体制造崩溃。

### 17.2 最终真实媒体半小时测试

全部实现和相关自动化测试通过后，额外执行一次持续 30 分钟的真实媒体计算测试：

- 真实媒体目录只读，不修改、不移动、不删除；
- 使用隔离的 Node 配置、数据库、日志和缓存；
- 执行真实枚举、文件读取、MD5、媒体探测和多 Worker 计算；
- 每 2 秒采集 CPU、内存、各物理磁盘吞吐、读取队列、Worker 忙碌数和阶段进度；
- 验证每盘线程、总读取线程、块大小和多 Worker 并行实际生效；
- 观察卡死、进度停滞、内存持续增长、Worker 无限崩溃和文件重复执行；
- 核对读取重试、文件故障数据库和日志没有异常误报；
- 测试结束后等待当前文件收尾或正常取消，不强制破坏真实媒体；
- 生成中文半小时测试报告和关键性能统计。

除这一次最终真实媒体测试外，不追加与本设计无关的验收套件。

## 18. 完成标准

只有同时满足以下条件才能声明完成：

1. 设置页能按机器唯一 ID 加载 Node 当前配置；
2. “保存并重启”由 Node 原子保存并完成自重启与重连确认；
3. 路径支持相对和绝对本机物理磁盘路径，网络路径被拒绝；
4. 不同物理磁盘可并行，同盘和总并发符合配置；
5. WorkerPool 可保持多个请求在途，CPU 不再被串行等待限制；
6. 任务中心每 2 秒显示真实阶段、文件进度、Worker 和失败详情；
7. Node 重启后运行详情清空，未完成任务只以新恢复任务出现；
8. Worker 崩溃文件不重试并可在数据库按机器唯一 ID 追溯；
9. 块读取三次均失败时跳过文件并记录疑似物理读取故障；
10. 视频联系表按 MD5 分目录保存并在文件存在时复用；
11. 磁盘已满时清理同盘全部符合条件的可再生文件且不触碰保护范围；
12. 所有相关自动化验证通过；
13. 最终真实媒体 30 分钟计算测试完成并形成报告。
