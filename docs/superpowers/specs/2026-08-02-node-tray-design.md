# 媒体节点托盘管理程序设计

## 状态

本设计已由项目负责人于 2026-08-02 逐节确认。

确认内容包括：

- 节点端采用常驻系统托盘程序；
- 主窗口采用页签式轻量界面；
- Agent、删除 Helper 和托盘程序自身均通过交互式控件配置，不提供原始
  JSON 编辑入口；
- Worker 继续由 Agent 自动管理，托盘程序只显示 Worker 状态；
- Agent 和删除 Helper 分别支持自动、手动启动；
- 删除 Helper 自动模式使用“以最高权限运行”的 Windows 计划任务；
- 删除 Helper 手动启动触发 UAC；
- 技术路线采用 Go + Wails/WebView2；
- 退出托盘程序默认不停止 Agent 或删除 Helper。

领域词汇以仓库根目录 `CONTEXT.md` 为准；技术选型记录在
`docs/adr/0002-use-go-wails-webview2-for-node-tray.md`。

## 背景

现有媒体节点需要部署并手工配置 `agent.exe`，可选部署管理员权限的
`helper.exe`。Agent 内部负责创建和监督 `worker.exe`。中央 `gui.exe`
只能依据 `gui.json` 中静态配置的 Agent 地址访问节点，不提供本机进程
配置、启动、停止或重启能力。

本设计新增每台媒体节点本地使用的节点托盘程序。它帮助操作员完成本机
Agent 和删除 Helper 的配置、状态观察和生命周期操作，但不取代中央 GUI，
不承担媒体计算，不直接管理 Worker，也不扩大删除权限。

## 目标

- 为每台 Windows 媒体节点提供常驻通知区域的 `nodetray.exe`。
- 使用统一、轻量、连贯的页签界面展示节点状态和配置。
- 通过输入框、选择器、开关、路径列表和目录浏览器修改参数。
- 对 Agent 提供启动、受控停止和重启。
- 对删除 Helper 提供配置、启动、受控停止和重启。
- 支持托盘程序登录后启动开关。
- 支持 Agent 自动或手动启动。
- 支持删除 Helper 自动或手动启动。
- 在普通用户会话中运行主界面，仅在确有必要时进行一次性 UAC 提权。
- 保持 Agent → Worker 的现有所有权和崩溃隔离关系。
- 保存配置前执行与运行程序一致的严格校验，并使用原子替换防止文件损坏。
- 状态和错误信息必须脱敏，不输出 PostgreSQL DSN、密码或删除确认令牌。

## 不在范围内

- 不把节点托盘程序建设为中央多节点管理后台。
- 不从中央 GUI 远程启动、停止或重启节点进程。
- 不把生命周期控制命令暴露到 Agent 的 TCP 监听端口。
- 不允许托盘程序直接启动、停止、重启或删除单个 Worker。
- 不把 Agent、Worker 或节点托盘程序改造成 Windows 服务。
- 不支持未登录用户时运行托盘界面。
- 不支持跨 Windows 账号管理节点组件。
- 不增加“删除节点”“卸载节点”或清理节点数据功能。
- 不允许节点托盘程序任意删除文件或目录。
- 不改变现有媒体特征算法、同步协议、删除确认语义或中央 GUI 工作流。
- 不在此设计中选择安装器格式或自动更新服务。

## 术语与启动语义

### 组件所有权

```text
媒体节点
  |
  +-- 节点托盘程序 nodetray.exe
  |     +-- 节点控制台窗口
  |     +-- 通知区域图标和菜单
  |     +-- Agent/Helper 配置与生命周期协调
  |
  +-- Agent agent.exe
  |     +-- Worker worker.exe × N
  |
  +-- 删除 Helper helper.exe（可选、管理员权限）
```

节点托盘程序管理 Agent 和删除 Helper 的配置及生命周期。Worker 的唯一
生命周期所有者仍然是 Agent；托盘程序只能读取 Agent 汇总的 Worker 状态。

### “开机启动”

托盘程序属于交互式用户会话，无法在用户登录前显示通知区域图标。因此
界面中不使用容易误解的“开机启动”，统一显示为“登录后启动托盘程序”。

该开关只控制当前部署账号登录后的托盘程序启动，不等同于 Windows 服务，
也不承诺在无人登录时运行 Agent。

### 自动与手动

- **Agent 自动**：托盘程序在登录后启动时，校验配置并启动 Agent。
- **Agent 手动**：托盘程序只显示 Agent 状态，操作员明确点击后才启动。
- **删除 Helper 自动**：预先创建的最高权限计划任务在同一账号登录后启动
  Helper。
- **删除 Helper 手动**：操作员点击启动，Windows 显示 UAC；同意后启动。

“自动”只描述登录后的启动策略，不表示崩溃后无限重启。Agent 或删除
Helper 异常退出后，托盘程序发出通知并等待操作员处理，不形成崩溃循环。

## 技术选型

### 选定方案

节点托盘程序采用 Go + Wails/WebView2：

- Go 负责配置模型、校验、进程监督、控制管道、Windows 通知区域、UAC、
  注册表登录启动和计划任务集成；
- Wails 建立 WebView 前端和 Go 后端之间的类型化调用边界；
- HTML/CSS/TypeScript 负责已确认的页签界面和统一组件样式；
- WebView 前端不得直接访问文件系统、进程、注册表、计划任务或凭据。

Wails 和 WebView2 的具体稳定版本在实施计划中钉死。生产构建不得使用远程
页面或开发服务器，所有前端资源嵌入 `nodetray.exe`。

### 未采用方案

- **纯 Go + 原生 Win32 控件**：运行依赖最少，但复杂配置表单、统一样式、
  高 DPI 和可访问性维护成本过高。
- **WPF/WinForms**：Windows 集成直接，但会重新引入项目架构已排除的 .NET
  技术栈；自包含发布还会显著增大包体。

### WebView2 运行时

- `nodetray.exe` 在初始化 Wails 前检查 WebView2 Runtime。
- Windows 11 仍必须实际检测，不凭操作系统版本假定存在。
- 缺失时使用随发布包提供的微软官方 Evergreen 引导程序。
- 安装前明确提示影响并由操作员确认；取消后不启动或修改任何节点组件。
- 不随默认发布包携带体积较大的 Fixed Version Runtime。
- 引导程序的来源、版本、SHA-256 和许可证信息必须进入发布清单。

## 运行时架构

```text
普通用户会话
┌──────────────────────────────────────────────────────────┐
│ nodetray.exe                                             │
│  ├─ Win32 通知区域与单实例                               │
│  ├─ Wails/WebView2 页签窗口                              │
│  ├─ 类型化配置服务                                       │
│  ├─ Agent/Helper 监督器                                  │
│  └─ 一次性提权动作的父端                                 │
│        │                                                 │
│        ├── Agent 控制管道 ── agent.exe ── worker.exe × N │
│        └── Helper 控制管道 ───────────────────────┐      │
└───────────────────────────────────────────────────│──────┘
                                                    │
管理员进程                                          │
┌───────────────────────────────────────────────────│──────┐
│ nodetray.exe --elevated-action（一次性）          │      │
│  ├─ 写入受保护 Helper 配置                        │      │
│  └─ 创建/更新/删除固定计划任务                    │      │
│                                                   │      │
│ helper.exe（可选、常驻） ◄────────────────────────┘      │
└──────────────────────────────────────────────────────────┘
```

### 单实例

- 托盘程序使用当前用户范围的命名互斥体保证单实例。
- 第二个实例不启动新的监督器，而是向现有实例发送“显示节点控制台”请求后退出。
- Agent 增加同节点单实例保护，防止托盘异常重启或人工启动造成重复 Agent。
- 删除 Helper 继续使用现有实例互斥体。

### 重新认领已运行组件

托盘程序启动或恢复时不得仅凭进程名认领组件：

1. 连接固定的本机控制管道；
2. 校验协议版本、组件类型和 `machine_id`；
3. 取得 PID、进程启动时间和可执行文件规范路径；
4. 使用 Windows 进程 API 交叉核对；
5. 核对成功后才显示为“已认领并运行”。

无法完成握手的同名进程不受托盘程序控制，界面显示“检测到未认领实例”，
要求操作员人工处理，不自动结束进程。

## 界面设计

### 总体视觉

- 单窗口、顶部页签，无常驻侧栏。
- 页签固定为“总览”“Agent”“删除 Helper”“程序设置”。
- 所有页面共用状态点、卡片、表单、按钮、边框、圆角和间距规则。
- 正常信息使用中性色；只有警告、异常和高风险操作使用强调色。
- 不以颜色作为唯一状态表达，必须同时显示文字或图标。
- 高级参数默认折叠。
- 窗口最小宽度不足时改为单列表单，不隐藏关键动作。

### 总览页签

总览显示三张一致的状态卡：

1. **Agent**：状态、PID、启动方式、运行时长；
2. **Worker**：`ready / expected`、最近异常；
3. **删除 Helper**：状态、启动方式、是否需要 UAC。

高频动作集中在状态卡下方：

- 重启 Agent；
- 停止 Agent；
- 启动删除 Helper；
- 打开完整日志目录。

总览不展示全部配置参数，不直接提供 Worker 操作。

### Agent 页签

Agent 页签包含：

- Agent 状态与启动、停止、重启操作；
- 常用配置表单；
- 折叠的高级配置；
- 只读 Worker 状态列表；
- “测试配置”“保存”“保存并重启 Agent”。

Worker 行只显示索引、PID、Ready 状态、当前任务摘要和最近错误，不显示启动、
停止、重启或删除按钮。

### 删除 Helper 页签

删除 Helper 页签包含：

- 当前运行状态、权限状态和启动方式；
- 允许目录列表；
- 拒绝目录列表；
- 默认软删除与硬删除开关；
- 回收目录和超时等高级参数；
- “测试配置”“授权并保存”“管理员启动”“停止”“重启”。

允许目录必须通过目录选择器添加，也可以粘贴绝对本地路径后由 Go 端验证。
每个条目独立显示和移除。空允许列表时禁用启动，并解释这是安全约束。

### 程序设置页签

- 登录后启动托盘程序；
- Agent 自动或手动启动；
- 删除 Helper 自动或手动启动；
- 关闭窗口时最小化到托盘；
- 状态刷新间隔；
- 通知级别；
- 打开配置备份或日志目录。

## 交互式配置模型

### 通用规则

- 前端只提交结构化字段，不获取或编辑原始 JSON。
- Go 后端把字段转换为现有严格配置类型后再验证。
- 未知字段不能通过 WebView 注入配置文件。
- 输入失焦时做局部校验，保存时做完整跨字段校验。
- 错误定位到具体字段或列表条目，不只显示通用失败弹窗。
- 保存成功后显示配置摘要和是否需要重启。
- “保存”不隐式重启正在运行的组件。
- 配置有未保存修改时，关闭窗口只隐藏到托盘；退出程序前提示处理修改。

### Agent 参数分组

| 分组 | 字段 | 控件 |
|---|---|---|
| 节点 | `machine_id` | 文本框，必填且唯一性提示 |
| 节点 | `listen_addr` | 主机和端口组合控件 |
| 节点 | `data_dir` | 目录选择器 |
| 数据库 | `pg_dsn` | 服务器、端口、数据库、用户、密码分段表单 |
| 扫描 | `use_everything` | 开关 |
| 扫描 | `scan.*` | 数字框、扩展名标签列表 |
| 同步 | `sync.*` | 带单位和范围的数字框 |
| Worker | `worker.count` | 正整数框 |
| Worker | `worker.exe_path` | 程序路径选择和签名/路径提示 |
| Worker | Worker 超时、内存、重生延迟 | 高级数字框 |
| 管线 | `pipeline.read_chunk_kb` | 高级数字框 |
| 缩略图 | `thumb.*` | 目录选择、尺寸和超时数字框 |
| IPC | `ipc.max_frame_mb` | 高级数字框 |
| 删除转发 | `delete.*` | 高级文本/数字框 |
| 调优 | `tuning.*` | 高级开关、数字框和回环监听框 |

`worker.crash_injection` 是测试能力，不进入生产界面。数据库连接在界面、通知、
剪贴板诊断和日志中必须脱敏。底层仍可按现有 Agent 合同序列化为 DSN，但
正式配置文件及其备份必须使用限制性 ACL。

### 删除 Helper 参数分组

| 分组 | 字段 | 控件 |
|---|---|---|
| 管道 | `pipe_name` | 高级文本框，固定前缀和字符校验 |
| 路径 | `allowed_roots` | 可增删目录列表，不能为空 |
| 路径 | `denied_roots` | 可增删目录列表 |
| 删除 | `default_mode` | 软删除/硬删除单选，默认软删除 |
| 删除 | `allow_hard_delete` | 独立高风险开关，新配置默认关闭 |
| 删除 | `recycle_dir_name` | 高级文本框 |
| 协议 | `max_entries_per_frame` | 1～2000 数字框 |
| 协议 | 读写超时 | 1～3600 秒数字框 |
| 日志 | `log_dir` | 目录选择器 |

加载现有配置时保留其显式值，不静默把既有硬删除配置改为关闭；界面必须以
明显警告显示，并要求保存前再次确认。

## 配置保存与恢复

### 存储位置

最终安装路径由后续安装设计确定，逻辑分区固定为：

- 程序文件：只读安装目录；
- 托盘设置：当前用户配置目录，只包含 UI 和启动策略；
- Agent 配置：节点共享配置目录，当前部署账号、Administrators、SYSTEM
  可访问；
- 删除 Helper 配置：节点共享配置目录，仅 Administrators、SYSTEM 可写；
- 备份：与对应正式配置相同目录并继承相同 ACL；
- 日志：使用 Agent `data_dir` 和 Helper `log_dir` 的现有约定。

不得把正式配置、凭据或删除令牌写入 WebView 用户数据目录。

### 原子保存

1. 前端提交结构化配置 DTO；
2. Go 端构建完整配置并执行现有加载器等价校验；
3. 在目标目录创建具有目标 ACL 的临时文件；
4. 编码 JSON、刷新文件内容并关闭句柄；
5. 将当前正式配置复制为同 ACL 的单份上次可用备份；
6. 使用 Windows 原子替换将临时文件替换为正式配置；
7. 重新从磁盘读取并校验；
8. 返回配置指纹和“需要重启”状态。

任一步骤失败时，旧正式配置保持可用。临时文件不得包含在错误消息中可被
普通日志读取的凭据内容。

### 恢复

- 配置损坏时不自动覆盖正式文件。
- 界面显示当前文件无效及脱敏原因，并提供“查看上次可用备份摘要”。
- 恢复必须由操作员明确确认。
- 恢复后仍需完整校验，再决定是否重启组件。

## 生命周期与状态模型

### 生命周期状态

Agent 和删除 Helper 使用相同的五态模型：

| 状态 | 含义 | 可用操作 |
|---|---|---|
| `stopped` | 未发现已认领实例 | 启动、编辑配置 |
| `starting` | 已创建进程，等待控制握手和健康条件 | 取消等待，不允许重复启动 |
| `running` | 控制握手成功 | 停止、重启、查看详情 |
| `stopping` | 已请求受控关闭，等待退出 | 等待；超时后可选择强制结束 |
| `failed` | 启动失败或异常退出 | 查看摘要、编辑配置、重新启动 |

“降级”是运行健康度，不是第六种生命周期状态。例如 Agent 进程和控制管道
正常但 PostgreSQL 暂时不可达，仍为 `running`，健康度显示警告。

### Agent 运行条件

Agent 只有同时满足以下条件才从 `starting` 进入 `running`：

- 进程仍存在；
- Agent 控制管道握手成功；
- `machine_id` 和可执行文件路径匹配；
- Agent 报告监听已就绪；
- Worker `ready == expected`。

Worker 未全部 Ready 时保持 `starting`；超过等待时间则进入 `failed`，但若
Agent 仍在运行，界面显示“Agent 运行但 Worker 未就绪”，不擅自结束。

### 删除 Helper 运行条件

- 进程或计划任务处于运行状态；
- Helper 控制管道握手成功；
- Helper 报告删除服务管道已监听；
- 配置指纹与托盘程序保存的版本一致。

### 停止与重启

- 停止优先通过本机控制管道请求受控关闭。
- Agent 停止时沿用现有 drain 与 Worker 清理逻辑。
- 删除 Helper 停止时不再接受新删除请求，并等待当前请求完成或达到受控
  超时。
- 超时后不得自动强制终止；界面显示影响并由操作员确认。
- 强制终止只针对已认领 PID，并再次核对 PID、启动时间和路径。
- 重启等于受控停止成功后重新启动；不得并行创建新实例。

### 异常退出

- 记录退出码、发生阶段、时间和脱敏错误摘要。
- 不无限自动重启。
- Worker 崩溃继续由 Agent 的现有重生策略处理，托盘程序只显示结果。
- 若 Agent 自身退出，托盘程序通知操作员，显示“查看详情”和“重新启动”。
- 若删除 Helper 退出，不影响 Agent 计算；删除能力显示不可用。

## 本机控制协议

### 目的

增加独立的本机控制管道，为托盘程序提供可信状态和受控关闭。生命周期命令
不得加入 Agent 现有 TCP 协议，因此中央 GUI 或局域网客户端不能远程启停
节点组件。

### 安全边界

- Agent 和删除 Helper 使用不同的固定控制管道。
- 管道 ACL 仅允许当前部署账号、Administrators 和 SYSTEM。
- 禁止 NETWORK SID 和匿名连接。
- 每次连接校验协议版本和组件类型。
- 服务端不接受任意可执行文件路径、配置路径或 shell 命令。
- 控制响应不包含完整 DSN、密码、确认令牌或媒体文件清单。

### 编码

复用仓库已有“4 字节大端长度 + msgpack map”的帧约定，但使用独立消息
类型和协议版本。所有新字段只追加，不复用现有删除消息。

请求公共字段：

```text
version
request_id
command
```

响应公共字段：

```text
version
request_id
ok
error_code
error_summary
```

### Agent 控制命令

- `status`：PID、启动时间、路径、`machine_id`、监听状态、配置指纹、Worker
  期望/Ready 数量、最近 Worker 错误摘要、同步健康度；
- `shutdown`：开始受控 drain 并停止 Agent；
- `subscribe`：可选状态变化流，减少窗口可见时的轮询。

不提供 `start` 或 `restart` 命令；启动由托盘监督器创建新进程，重启由托盘
组合停止和启动。

### 删除 Helper 控制命令

- `status`：PID、启动时间、路径、配置指纹、删除服务就绪、活动请求数；
- `shutdown`：停止接收新请求并等待活动请求结束；
- `subscribe`：可选状态变化流。

控制管道与现有删除服务管道分离，防止状态操作和删除事务互相干扰。

## 进程监督

### Agent 启动

1. 验证没有已认领 Agent；
2. 验证 Agent 配置、数据目录和可执行文件；
3. 使用绝对路径和显式 `-config` 参数创建进程；
4. 不通过 shell 拼接命令行；
5. 记录进程句柄、PID、启动时间和程序路径；
6. 等待控制管道和 Worker Ready；
7. 成功后发布状态事件。

托盘程序退出时不使用“关闭 Job Object 即杀死子进程”的策略，确保默认退出
托盘后 Agent 继续运行。托盘重启后通过控制握手重新认领。

### 删除 Helper 手动启动

1. 普通窗口校验 Helper 配置摘要；
2. 使用 `ShellExecute` 的 `runas` 发起管理员启动；
3. Windows 显示 UAC；
4. 取消 UAC 时不修改状态或配置；
5. 同意后启动 Helper，并等待控制管道握手。

### 删除 Helper 自动启动

- 使用固定任务目录和固定任务名，禁止用户输入任意任务名。
- 触发器为配置账号登录。
- 使用同一账号的交互式令牌和“最高权限运行”。
- 操作为绝对路径 `helper.exe` 和固定配置路径。
- 创建、修改、删除任务需要一次性提权动作。
- 普通托盘程序只读取任务状态和请求运行，不持有管理员权限。
- 计划任务定义与期望不一致时显示“任务配置漂移”，不得静默覆盖。

## 一次性提权动作

### 进程模式

主程序保持 `asInvoker`。需要管理员写入时，以同一可执行文件启动受限模式：

```text
nodetray.exe --elevated-action --nonce <随机值>
```

不在命令行传递配置内容、密码、媒体目录清单或任意目标路径。

### 请求传递

1. 普通进程创建随机 nonce 和仅限当前用户/Administrators/SYSTEM 的临时
   命名管道；
2. 通过 `runas` 启动提权子进程；
3. 子进程连接管道并完成 nonce 握手；
4. 普通进程发送结构化、带操作枚举的请求；
5. 提权进程重新执行全部安全校验；
6. 只写固定 Helper 配置位置或操作固定计划任务；
7. 返回结构化结果后立即退出。

提权进程不得提供通用文件写入、通用命令执行、任意注册表或任意计划任务
接口。

## 托盘、窗口与通知

### 通知区域菜单

- 节点名称和总体健康度；
- Agent 状态；
- Worker `ready / expected`；
- 删除 Helper 状态；
- 打开节点控制台；
- 重启/停止 Agent；
- 管理员启动或停止删除 Helper；
- 打开日志目录；
- 程序设置；
- 退出托盘程序。

双击图标打开节点控制台。菜单动作与主窗口使用同一个监督器状态机，执行中
自动禁用冲突操作。

### 窗口关闭

- 点击窗口关闭按钮只隐藏到通知区域。
- 关闭不会停止 Agent 或删除 Helper。
- 未保存修改保留在当前托盘进程内，并在真正退出前提示。

### 退出

退出对话框提供两个明确选项：

1. **仅退出托盘程序**：默认选项，Agent 和删除 Helper 保持当前状态；
2. **停止组件后退出**：受控停止 Agent；若删除 Helper 正在运行，也请求
   受控停止。

停止组件失败或超时时，不继续静默退出，交由操作员选择返回、仅退出托盘或
确认强制终止已认领进程。

### 通知策略

通知只在状态变化或需要操作员介入时产生：

- Agent/Helper 启动失败；
- Agent/Helper 异常退出；
- Worker 长时间未全部 Ready；
- 组件从异常恢复；
- 配置保存失败；
- 需要 UAC；
- 计划任务配置漂移。

周期性心跳、稳定运行状态和重复的同一错误不反复通知。相同错误在冷却时间
内合并，并在控制台中累计次数。

## 登录启动

- 托盘程序使用当前用户范围的登录启动项，不需要管理员权限。
- 开关关闭时只删除本程序自己创建的固定启动项。
- 不修改其他启动项。
- 登录启动命令使用绝对程序路径，不包含配置内容或凭据。
- 程序移动或升级后，由安装/升级流程更新启动项；托盘程序检测路径漂移并
  提示，不自动扫描磁盘寻找替代程序。

## 状态刷新与资源占用

- 进程退出优先使用进程句柄事件，不依赖高频轮询。
- 窗口可见时，健康状态最多每 3 秒刷新一次。
- 窗口隐藏时，稳定状态最多每 10 秒检查一次。
- 管道状态变化流可用时优先订阅，轮询作为恢复保障。
- 不持续读取整份日志；最近事件通过有界缓冲或按需读取日志尾部。
- 前端列表和事件记录均有界，不无限累积 DOM 节点或内存对象。

轻量验收在 Windows 11 x64 参考机上记录：

- 窗口隐藏并稳定 2 分钟后，托盘和 WebView2 相关进程总私有工作集目标不
  超过 256 MiB；
- 稳定状态下 5 分钟平均 CPU 目标低于单核的 1%；
- 状态刷新不得明显增加 Agent/Worker 的媒体处理延迟。

若 WebView2 版本导致资源波动，验收报告必须记录实测，不得只以目标替代
证据。

## 安全设计

### WebView

- 只加载嵌入的本地资源。
- 生产构建关闭开发工具和任意导航。
- 设置严格 CSP，不允许远程脚本、内联动态代码或任意网络请求。
- 外部文档链接必须经 Go 端白名单确认后交给系统浏览器。
- 前端无法自行构造任意文件路径、进程参数或管理员动作。

### 路径

- 所有可执行文件和配置路径在 Go 端规范化为绝对本地路径。
- Helper `allowed_roots` 继续执行现有强制规范化和系统目录拒绝策略。
- 新配置不得把盘符根、系统目录或过宽目录作为删除白名单。
- 托盘程序不提供目录清理、删除配置目录或删除日志目录功能。
- 路径列表的移除只修改配置，不删除对应媒体文件。

### 凭据

- 数据库密码输入框默认隐藏。
- 完整 DSN 不出现在 UI 状态、通知、日志、剪贴板诊断或崩溃报告中。
- Agent 正式配置及备份使用限制性 ACL。
- 提权命令行不包含凭据。
- 测试使用合成凭据，不把真实值写入仓库或证据目录。

### 进程操作

- 不使用 `taskkill /IM`、进程名通配或全局进程扫描作为结束手段。
- 只控制通过句柄创建或经控制管道完整认领的 PID。
- 强制终止前重新核对 PID、启动时间和可执行文件路径。
- 不启动、停止或修改中央 GUI、PostgreSQL、Everything 服务或其他无关进程。

## 错误处理

### 配置错误

- 保存前错误：定位字段并拒绝写入。
- 磁盘写入错误：保留旧配置，清理可安全识别的临时文件。
- 写入后复读失败：报告保存失败，提供上次可用备份，但不自动重启组件。
- 运行配置与磁盘配置指纹不同：显示“需要重启”，不谎报已生效。

### Agent 错误

- 配置无效：不创建进程。
- 数据目录不可写：显示路径类别和错误码，不显示敏感内容。
- PostgreSQL 不可达：若 Agent 已按现有语义继续运行，显示降级警告，不把
  Agent 判定为已停止。
- Worker 未就绪：显示期望数、Ready 数和最近脱敏错误。
- 异常退出：保留退出码并等待人工重启。

### 删除 Helper 错误

- UAC 取消：保持旧配置和旧任务，不作为组件崩溃。
- 允许目录为空：禁止保存为可启动配置。
- Helper 配置保存失败：旧配置保持可用。
- 计划任务创建失败：显示 Windows 错误码和脱敏说明。
- Helper 管道不可达：显示运行状态不确定，不自动结束管理员进程。
- 活动删除请求阻止停止：显示活动数量并继续等待或由用户取消停止。

### WebView2 错误

- Runtime 缺失：原生提示安装，不启动 Agent/Helper。
- Runtime 初始化失败：记录本地脱敏诊断并退出界面初始化；不得进入重复启动
  循环。
- 前端崩溃：监督器仍保持进程状态，不因 UI 崩溃结束 Agent/Helper；托盘
  程序可尝试重建一次窗口，失败后提示重启托盘程序。

## 兼容与迁移

- 现有 `agent.json` 和 `helper.json` 格式继续作为运行程序合同。
- 首次运行可导入现有配置；导入后立即用当前严格加载器验证。
- 不认识的字段导致导入失败，不静默丢弃。
- 导入不自动启动组件。
- 现有命令行启动方式继续可用，但托盘程序无法安全认领没有控制协议的旧
  版本，必须显示版本不兼容。
- 中央 `gui.json` 和中央 Web GUI 不因节点托盘程序自动修改。
- 节点 `machine_id` 或 Agent 地址变化时，仅提示管理员同步更新中央配置。

## 构建与发布

- `scripts/build.ps1` 增加显式节点托盘构建开关和产物检查。
- 前端依赖使用锁文件，生产构建不从网络动态加载资源。
- Wails、Node、Go 和 WebView2 引导程序版本进入供应链清单。

  WebView2 官方引导程序及其许可证/哈希记录。
- `nodetray.exe` 使用 `asInvoker` 清单；不得整体标记
  `requireAdministrator`。
- `helper.exe` 继续使用管理员权限清单。
- 生产包不包含前端开发服务器、源映射、调试端口或测试凭据。

## 验收标准

### 功能

- 登录后只存在一个托盘实例。
- 主窗口符合确认的页签式轻量设计。
- 操作员无需打开文本编辑器即可完成全部支持参数配置。
- Agent 可以启动、受控停止和重启。
- Worker 状态可见但不存在直接管理入口。
- 删除 Helper 可以配置、手动启动、自动启动、受控停止和重启。
- Helper 自动模式的任务以最高权限、同一账号、登录触发运行。
- 窗口关闭只隐藏；默认退出不停止组件。

### 安全

- 主托盘程序全程以普通用户权限运行。
- UAC 只用于 Helper 手动启动、受保护配置和计划任务操作。
- 提权模式不提供通用管理员代理能力。
- 生命周期控制只通过本机受 ACL 保护的管道。
- 不按名称批量终止进程。
- Helper 白名单为空或过宽时不能启动。
- UI、日志、通知和测试证据不包含真实凭据或确认令牌。

### 可靠性

- 配置写入失败不破坏旧配置。
- 托盘程序退出或崩溃不连带停止 Agent/Helper。
- 托盘重启可以安全认领兼容的已运行组件。
- 组件异常退出不形成无限重启循环。
- 停止超时不自动强制结束。
- 运行配置与磁盘配置差异可见。

### 证据

- 单元和前端测试结果；
- Windows 单实例、Agent 生命周期、重新认领的动态记录；
- Helper UAC 和计划任务的授权动态记录；
- ACL 检查结果；
- 无凭据日志扫描结果；
- WebView2 缺失处理记录；
- 窗口隐藏后的 CPU 和内存实测。

未运行的真实 UAC、计划任务、登录启动或进程动态验收必须标记为
`BLOCKED_NOT_RUN_DYNAMIC`，不得因静态检查通过而写成 PASS。

## 已确认设计结论

- 使用节点托盘程序，而不是扩展中央 GUI 做远程进程控制。
- 使用 Go + Wails/WebView2，不重新引入 .NET。
- 使用页签式轻量界面和统一组件样式。
- 所有配置通过交互式表单修改，不直接编辑原始文件。
- Worker 完全归 Agent 管理。
- 主程序普通权限，管理员能力按需、一次性、受限。
- 删除 Helper 自动模式使用最高权限计划任务。
- 登录启动不等同 Windows 服务。
- 默认退出托盘不停止组件。
- 配置使用严格校验、ACL、原子替换和单份上次可用备份。
- 状态由进程身份和本机健康握手共同判定。
- 生命周期接口不暴露到网络。
