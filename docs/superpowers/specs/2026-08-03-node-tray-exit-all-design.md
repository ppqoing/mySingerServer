# NodeTray 完整退出设计

日期：2026-08-03

## 目标

托盘右键菜单中的“退出”必须是完整退出，而不是仅关闭或隐藏控制台窗口。操作完成后，由当前托盘可信管理的 Helper、Agent、Worker 和托盘程序都不再运行。

## 当前问题

托盘菜单收到 `ExitTray` 命令后只发送 `window-close-requested` 前端事件。控制台窗口隐藏时，该事件不会触发可见的退出对话框，也不会调用后端退出服务，因此用户看到“退出无效”。

## 退出流程

1. 托盘右键“退出”直接调用后端完整退出操作，不再依赖前端窗口事件。
2. 先请求 Helper 优雅停止。
3. Helper 停止失败或超时后，对托盘已可信认领的 Helper 执行强制停止。
4. 再请求 Agent 优雅停止。Agent 的正常关闭流程负责停止其 Worker 池并等待 Worker 退出。
5. Agent 停止失败或超时后，对托盘已可信认领的 Agent 执行强制停止；其受管 Worker 进程随 Agent 进程树一并结束。
6. Helper、Agent 的停止流程均成功后，调用 Wails 退出函数结束托盘程序。

## 安全边界

- 只强制结束已经通过组件类型、可执行文件路径、进程标识和配置摘要握手并被托盘可信认领的进程。
- 不按进程名扫描并强杀其他实例。
- 如果组件未被可信认领且无法优雅停止，完整退出返回失败，托盘保持运行并报告稳定、脱敏的错误摘要。
- 不改变窗口右上角关闭按钮的“最小化到托盘”设置语义。

## 错误处理

- 优雅停止成功：继续处理下一个组件。
- 优雅停止失败或超时：自动尝试对应组件的强制停止。
- 强制停止成功：继续退出流程。
- 强制停止失败：停止退出流程，不调用托盘退出函数，并向现有通知通道报告退出失败。
- 所有返回给界面的错误继续使用现有脱敏逻辑，不输出配置内容或凭据。

## 测试范围

- 右键“退出”直接调用完整退出操作，且不再发送 `window-close-requested`。
- Helper 在 Agent 之前停止。
- 优雅停止成功时不调用强制停止。
- 优雅停止失败或超时时调用对应的强制停止。
- Agent 停止成功代表其 Worker 关闭流程完成。
- 任一强制停止失败时不退出托盘。
- 所有组件停止后只调用一次托盘退出函数。
- 窗口关闭按钮原有行为保持不变。

## 非目标

- 不增加按进程名清理任意 Agent、Worker 或 Helper 的功能。
- 不改变组件启动、重启、开机启动和配置保存行为。
- 不重构托盘菜单或控制台界面样式。
