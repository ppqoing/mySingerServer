# GUI 与 NodeTray 本地任务可视化路径选择设计

日期：2026-08-13
状态：已确认设计

## 1. 背景

当前两个任务入口都依赖手工输入路径：

- NodeTray 的“本地任务”页面只接受一个扫描目录文本值。
- GUI 的“扫描任务”页面先选择 Agent，再通过竖线分隔的文本输入提交一个或多个根目录。

这种方式容易出现路径输错、管理机路径与目标 Agent 路径混淆、重复根目录和父子目录重复扫描等问题。本设计为 GUI 与 NodeTray 增加可视化目录选择，同时保留手工输入能力。

## 2. 已确认目标

1. GUI 与 NodeTray 都支持可视化选择任务路径。
2. 一次任务支持多个扫描根目录。
3. GUI 浏览并选择当前目标 Agent 所在机器的路径，而不是 GUI 管理机的路径。
4. NodeTray 使用 Windows 原生目录选择窗口选择本机路径。
5. 浏览界面同时展示目录和文件，但文件不可选中。
6. GUI 中隐藏项和系统项默认不显示，可由用户显式开启；NodeTray 原生窗口跟随 Windows 资源管理器的显示设置。
7. 保留手工输入绝对路径和 UNC 路径的能力。
8. 路径选择、路径保存和任务创建均不需要 UAC。

## 3. 非目标

- 不浏览或传输文件内容。
- 不提供文件预览、文件上传或文件下载。
- 不主动发现局域网共享；UNC 路径只能手工输入或从已知 UNC 路径继续浏览。
- 不为路径选择新增配置文件或数据库表。
- 不为本功能新增 GUI-Agent 共享令牌或 Manager 认证握手；继续沿用现有可信内网和防火墙边界。
- 不改变 Helper 的提权边界；只有启动 Helper 仍可能需要 UAC。
- 不统一 GUI 与 NodeTray 的选择窗口外观，两端只统一选择结果和路径规则。

## 4. 方案选择

采用混合方案：

- NodeTray 调用 Windows 原生目录选择窗口。
- GUI 使用页面内的远程 Agent 文件浏览弹窗。
- 两端都将选择结果写入同样的多根目录列表，再通过现有任务 `roots` 字段提交。

未采用纯浏览器目录选择，因为浏览器只能访问管理机上的用户选择，无法可靠得到目标 Agent 的绝对路径。未采用 NodeTray 自定义远程浏览器，因为本机使用 Windows 原生窗口更自然，且无需额外经过 Agent 枚举协议。

## 5. 总体数据流

### 5.1 NodeTray

```text
本地任务页面
  -> Windows 原生目录选择窗口
  -> 已选根目录列表
  -> CreateLocalTask
  -> 本机 Agent
```

- 每次窗口选择一个目录，用户可重复打开窗口添加多个目录。
- 取消窗口不会修改现有列表。
- 选择完成后仅更新页面草稿，点击“创建任务”才正式提交。
- 优先使用 Wails 的 Windows 原生目录选择能力；验收以“文件可见但不可选”为准。如果 Wails 封装在当前 Windows 版本隐藏文件，则由 Windows 平台适配器调用原生 `IFileDialog`，但前端接口保持不变。

### 5.2 GUI

```text
扫描任务页面
  -> 选择在线且已认领的 Agent
  -> 打开远程文件浏览弹窗
  -> GUI HTTP API
  -> 现有 GUI-Agent TCP 长连接
  -> 目标 Agent 枚举当前层级
  -> 返回磁盘、目录和文件
  -> 已选根目录列表
  -> 现有扫描任务提交
```

- 未选择 Agent、Agent 离线或未认领时，选择按钮不可用。
- 切换 Agent 会关闭当前浏览弹窗并取消或丢弃未完成请求，但不会把前一个 Agent 的路径带到新 Agent；已有选择需要清空并明确提示。
- Agent 只枚举当前层级，不递归遍历目录树。

## 6. 界面交互

### 6.1 通用根目录列表

GUI 与 NodeTray 都使用相同的交互语义：

- “选择目录…”：打开对应的可视化选择器。
- “手工添加”：输入绝对 Windows 路径或 UNC 路径。
- 已选目录逐项显示，每项可移除。
- 选择器关闭后可以继续添加其他目录。
- 点击“创建任务”前显示最终根目录列表。

### 6.2 GUI 远程浏览弹窗

弹窗包含：

- 当前 Agent 名称或机器 ID。
- 面包屑路径与返回上级操作。
- 磁盘入口：目标 Agent 可访问的本地盘、移动盘和已映射网络盘。
- 当前目录条目列表。
- “显示隐藏/系统项”开关。
- “取消”和“添加当前目录”按钮。

目录条目可进入和选择。文件正常显示名称和文件类型，但使用不可选择状态。用户进入目标目录后，必须点击“添加当前目录”才加入根目录列表，避免单击导航造成误选。

无权限目录不在初始列表阶段逐个探测，避免大量额外 I/O；用户首次进入失败后，该条目在当前弹窗会话中标记为“不可访问”并禁止继续选择。

### 6.3 NodeTray 原生窗口

- Windows 原生窗口从当前路径或合理的默认位置打开。
- 文件可见但不可选择，只有目录能够确认。
- 隐藏项和系统项是否显示跟随 Windows 资源管理器设置；Wails 2.12 的 Windows 目录窗口不会转发应用层 `ShowHiddenFiles`，本功能不为此重写自定义浏览器。
- 每次确认一个目录并返回 NodeTray 页面。
- 多目录通过重复点击“选择目录…”完成。

## 7. 路径规则

手工输入和可视化选择使用同一套规则：

1. 只接受绝对 Windows 路径或合法 UNC 路径。
2. 不接受相对路径，不展开 `%VAR%` 等环境变量。
3. 使用 Windows 大小写不敏感规则比较路径。
4. 清理多余分隔符和末尾分隔符后去重，磁盘根目录除外。
5. 已选择父目录时，拒绝再次添加它的子目录，并提示该子目录已被覆盖。
6. 已选择一个或多个子目录后再添加父目录时，要求用户确认；确认后用父目录替换被覆盖的子目录。
7. 允许选择磁盘根目录，但必须在提交前明确展示完整路径。
8. 正式创建任务时由 Agent 再次验证目录存在性和访问权限，以处理选择后目录删除、卷移除或权限变化。

## 8. GUI 远程浏览接口

### 8.1 HTTP API

新增接口：

```text
POST /api/agents/{machine_id}/filesystem/browse
```

路径放在 JSON 请求体中，不放入 URL、查询参数或普通访问日志。

请求概念字段：

```text
path          当前目录；空值表示列出磁盘
show_hidden   是否显示隐藏项和系统项
cursor        可选的不透明分页游标
limit         每页数量，默认 200，服务端限制最大值
```

响应概念字段：

```text
request_id    请求关联标识
current_path  当前规范化路径
parent_path   上级路径；磁盘入口为空
entries       当前页条目
next_cursor   下一页游标；无下一页时为空
```

每个条目包含名称、完整路径、类型、隐藏/系统属性和是否可选择。类型至少包括 `drive`、`directory`、`file`。只有 `drive` 和 `directory` 可以成为根目录。

### 8.2 Agent TCP 协议

在现有协议中追加新的目录浏览请求和响应消息类型，不复用已有编号，也不改变现有消息含义。协议允许追加消息，因此不因本功能修改既有任务消息格式。

- 每个请求携带不可复用的 `request_id`。
- GUI 连接池维护有限数量的待响应请求，并按 `request_id` 配对。
- Agent 响应只能回到发起请求的同一条 GUI-Agent 连接。
- Agent 断线时立即结束对应等待。
- HTTP 请求取消、弹窗关闭或切换 Agent 后，GUI 删除待响应项并忽略迟到响应；Agent 侧在可取消边界内尽快结束枚举。
- 浏览请求设置独立超时，不能阻塞心跳、扫描任务或结果消息处理。

### 8.3 枚举规则

- 空路径列出目标 Agent 账户可见的盘符。
- 普通路径只列出直接子项。
- 目录优先、文件其次，同类按 Windows 名称规则排序。
- 默认每页 200 项，使用不透明游标继续加载。
- 不读取文件内容，不计算哈希，不生成缩略图。
- 不自动扫描网络邻居。
- 响应受到现有协议帧大小限制，超过限制时必须分页而不是截断为不完整结构。

## 9. 错误与状态

GUI 使用稳定错误码和中文摘要，至少区分：

- Agent 不在线或未认领。
- Agent 在浏览过程中断线。
- 请求超时。
- 路径格式无效。
- 路径不存在。
- 权限不足。
- 磁盘或网络卷不可用。
- 目录内容发生变化或无法继续分页。
- 未分类的枚举失败。

错误显示在浏览弹窗内部。失败不会清空已选根目录，用户可以返回上级、重新加载或关闭弹窗。原始系统错误不直接回显完整路径；生产日志只记录稳定错误码、Agent 标识和路径摘要 `path_id`。

## 10. 安全与权限边界

- NodeTray 本机选择、GUI 远程浏览和任务创建都不触发 UAC。
- Agent 使用自身运行账户枚举目录；实际无法访问的目录不能继续浏览或加入根目录列表。
- 当前 GUI-Agent TCP 连接没有 Manager 身份认证；本功能按已确认决策继续沿用现有可信内网和防火墙边界，不把该连接描述为已认证连接。
- 部署时应限制 Agent 监听端口只对受信任的 Manager 主机开放；新增目录浏览消息不会额外开放 HTTP 或文件共享端口。
- Agent 不执行请求路径中的命令、环境变量或 shell 展开。
- 不提供文件读取接口，文件条目始终不可选择。
- GUI HTTP 接口沿用现有 Manager 页面访问边界；请求体和日志不得泄漏完整路径。

## 11. 状态与持久化

- 浏览弹窗状态和已选根目录在页面内维护。
- 浏览历史不单独写入磁盘或数据库。
- 创建任务后，根目录继续存入现有任务信封的 `roots` 字段，由现有恢复逻辑持久化。
- 切换目标 Agent 时清空未提交的路径选择，避免把另一台机器的路径误派发。
- NodeTray 关闭或刷新页面时，不恢复尚未提交的草稿路径。

## 12. 实现范围

预计涉及以下边界：

- `internal/proto`：目录浏览请求、响应和条目结构。
- `internal/agent`：现有 GUI-Agent TCP 请求处理和 Windows 文件系统枚举服务。
- `internal/gui`：HTTP 路由、连接池请求配对、超时与断线处理。
- `webui`：远程浏览弹窗、多根目录列表及路径重叠提示。
- `nodetray`：原生目录选择后端方法。
- `nodetray/frontend`：本地任务多根目录列表和原生选择入口。

不新增数据库迁移，不修改 Helper 配置，不改变扫描和分析算法。

## 13. 聚焦验证

遵循小范围验证，不扩大全仓审查：

1. 路径规则：大小写去重、父子重叠、父目录替换确认、UNC 和非法相对路径。
2. Agent 枚举：磁盘、普通目录、文件不可选、隐藏/系统开关、无权限和路径消失。
3. GUI 后端：请求配对、Agent 断线、超时、取消和迟到响应。
4. GUI 前端：必须先选 Agent、多目录添加移除、文件不可选择、分页与错误保留。
5. NodeTray：原生选择结果加入列表、取消不修改、重复选择不重复添加。
6. 一次人工 Windows 验收：NodeTray 原生窗口与 GUI 远程 Agent 浏览各完成一次多目录任务创建。

## 14. 验收标准

- NodeTray 能连续选择多个本机目录并创建任务。
- GUI 能浏览指定远程 Agent 的磁盘、目录和文件。
- 文件可见但无法加入根目录。
- GUI 中隐藏项和系统项默认不显示，开启后可以显示；NodeTray 跟随 Windows 资源管理器设置。
- Agent 切换、离线、超时、无权限和目录消失都有明确反馈。
- 重复路径及父子重叠路径不会造成重复扫描。
- 手工输入路径仍然可用，并遵循相同校验规则。
- 整个选择和任务创建流程不申请管理员权限。
