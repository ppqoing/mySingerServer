# M6 Performance Tuning and Benchmarking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded Agent performance telemetry and all M6 benchmark/reporting tools, prove them with automated tests and a short read-only two-SSD benchmark, and generate a safe manual long-run driver.

**Architecture:** A small `internal/stats` collector samples existing worker counters and receives scan lifecycle hooks, retaining a bounded ring and writing JSONL. The Agent exposes snapshots through the already-reserved protocol messages and optional loopback pprof, while standalone Go commands perform read-only I/O, isolated PostgreSQL, first-screen, generated-corpus, soak, and report workloads. PowerShell drivers enforce safety and evidence limits.

**Tech Stack:** Go 1.22 module compatibility, Go standard library, `golang.org/x/sys/windows`, `golang.org/x/sync/semaphore`, msgpack v5, pgx v5/PostgreSQL, lumberjack v2, PowerShell 7.

## Global Constraints

- `docs/superpowers/specs/2026-07-29-m6-tuning-design.md` is authoritative where `docs/details/M6-tuning.md` assumes YAML, duplicates current scheduling, or uses unsafe/unbounded examples.
- `I:\tmp` and `H:\pik\00000000000` are read-only source corpora. No M6 code or script may rename, delete, write, touch timestamps/attributes, or generate files below them.
- Automated source-corpus benchmarking is limited to 10,000 files per root and 30 minutes total.
- HDD utilization and 24-hour stability remain `NOT_RUN`; the M6 todo remains unchecked unless those original gates are later executed and pass.
- Production sync remains a five-minute or 50,000-row trigger and a maximum 5,000-row transaction.
- PostgreSQL credentials never appear in command lines, stdout/stderr, JSON/Markdown evidence, or source files.
- pprof is disabled by default and accepts loopback addresses only.
- No UAC, package installation, global process kill, or production configuration rewrite.
- No Git repository exists. Each task ends with a changed-file and fresh-test evidence checkpoint instead of a commit.
