# M5 Safe Delete Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a safe, auditable GUI → Agent → elevated Helper delete flow whose default is same-volume soft delete, whose explicit hard-delete path clears the read-only bit, and whose complete Windows acceptance suite never touches user media.

**Architecture:** Extend the existing uint8/msgpack protocol, add a small resident Windows Helper behind a local ACL-restricted named pipe, keep Agent unprivileged as a forwarder/auditor/state synchronizer, and add server-resolved confirmation plus HTTP-polled task aggregation to the existing GUI. Security validation is repeated immediately before every mutation, and ambiguous destructive requests are surfaced rather than replayed.

**Tech Stack:** Go 1.26 (module compatibility remains Go 1.22), `github.com/Microsoft/go-winio` v0.6.2, `golang.org/x/sys/windows` v0.28.0, msgpack v5, SQLite, pgx v5/PostgreSQL 16, embedded HTML/CSS/JavaScript, MinGW `windres`, PowerShell verification.

## Global Constraints

- `docs/superpowers/specs/2026-07-28-m5-delete-design.md` is authoritative when `docs/details/M5-delete.md` contains contradictory auto-UAC, idle-exit, auto-restart, or hard-default examples.
- Helper is manually/deployment-started, `requireAdministrator`, resident, and stopped only by explicit `MsgShutdown`, process control, or console shutdown. Agent never calls `runas`, `ShellExecute`, `os/exec`, or any auto-start/restart path for Helper.
- Soft delete is the default. Hard delete must be explicitly selected after the second confirmation and remains locally disableable with `allow_hard_delete=false`.
- Reuse `internal/proto.Conn`, the existing uint8 message numbers, and the existing msgpack map envelope. Do not add string-valued message types or a second frame codec.
- Helper accepts only local drive-letter file paths under normalized `allowed_roots`; it rejects UNC, device/volume-relative paths, directories, duplicate entries, every reparse component, denied roots, and direct access to its recycle tree.
- Every target and every existing recycle-destination ancestor is revalidated immediately before attribute change, rename, or removal.
- `I:\tmp` and `H:\pik\00000000000` are read-only source corpora. They must never appear in Helper `allowed_roots`, delete requests, test enumeration, or cleanup commands.
- Destructive tests use only a run-unique directory below `.superpowers/tmp`, mapped to a run-unique free drive letter with `subst`; therefore `<drive>:\$DedupRecycle` also resolves inside that isolated directory.
- No destructive request is automatically replayed after Helper, Agent, or GUI failure. A user must prepare and confirm a new request.
- No Git repository exists. Replace commit steps with an exact changed-file report, an independent code review, and fresh fail-closed controller evidence.
- Second independent Windows validation is completed on `codex-192-168-1-6`;
  require `SECOND_WINDOWS_STATUS=VERIFIED_ON_SECOND_WINDOWS`.
- Examples and evidence must not contain live PostgreSQL credentials, confirmation tokens, or machine secrets.

### Task 3: Per-Item Soft/Hard Delete Processor

**Files:**
- Create: `internal/helper/delete.go`
- Create: `internal/helper/delete_windows.go`
- Create: `internal/helper/delete_windows_test.go`

**Interfaces:**

```go
type Processor struct {
	cfg       Config
	validator *Validator
}

func NewProcessor(Config, *Validator) *Processor
func (p *Processor) Process(context.Context, proto.DeleteTask) proto.DeleteReport
```

Frame-level validation happens before the first target is touched. Invalid confirmation, mode, hard-disable policy, task ID, sequence envelope, count, empty entry, or duplicate normalized path returns a report covering every input with the same stable frame error.

For this task, `task_id` is a non-nil canonical lowercase RFC 4122 UUID,
`seq <= last_seq`, and the entry count is `1..cfg.MaxEntriesPerFrame`.
Structural frame errors use `E_BAD_PATH`; precedence is
`E_NOT_CONFIRMED`, then `E_BAD_MODE`, then structural `E_BAD_PATH`. An empty
mode always means `soft` regardless of `Config.DefaultMode`, so hard delete
can only be requested explicitly. Duplicate detection uses successful local
absolute normalization plus Windows `OrdinalIgnoreCase`; malformed non-empty
paths that cannot be normalized remain per-item failures. Every report echoes
the request's `task_id`, `seq`, and `last_seq`, and contains one result for
each input path in input order.

The soft-delete `relative` component is relative to the volume root, not just
the matched allowed root. Processor tests therefore use only a run-unique
temporary directory exposed through a dynamically allocated temporary
`subst` drive, so the corresponding volume-root recycle tree is also inside
that temporary directory. Tests must never enumerate or mutate `I:\tmp` or
`H:\pik\00000000000`. Drive-letter equality is not proof of actual
same-volume identity because an allowed root may be below a mounted-folder
ancestor. Resolve the source and destination mount points with
`GetVolumePathNameW`, resolve both to volume GUID paths with
`GetVolumeNameForVolumeMountPointW`, and compare those GUID paths with Windows
`OrdinalIgnoreCase` before the first destination mutation and again
immediately before the move. Lookup failure or mismatch fails closed as
`E_RECYCLE_FAILED`. A `QueryDosDeviceW` fallback is allowed only for a
`subst`-style alias whose input volume is exactly an ASCII drive letter and
whose returned first target is exactly `\??\` followed by a path that passes
the same local ASCII drive-letter absolute normalization as Helper
configuration; UNC, `UNC\...`, volume-GUID/device, root-relative,
non-letter-drive, ambiguous multi-target, or otherwise malformed mappings
fail closed. Common Win32 mutation failures map before the
operation-specific fallback: missing/path-missing to `E_NOT_FOUND`,
sharing/lock violation to `E_IN_USE`, access denied to `E_ACCESS_DENIED`;
readonly-clear failures use `E_READONLY`, remaining rename failures use
`E_RECYCLE_FAILED`, and remaining remove/cancellation failures use
`E_DELETE_FAILED`. On cancellation, already completed results are preserved
and every not-yet-started entry receives `E_DELETE_FAILED` without mutation.

- `confirmed=false` leaves all files unchanged with `E_NOT_CONFIRMED`;
- omitted mode resolves to `soft`, while unknown mode and disabled hard mode use `E_BAD_MODE`;
- 2001 entries, invalid sequence metadata, and normalized duplicates are all-or-nothing frame rejects;
- soft delete preserves SHA-512, uses the same volume, produces `<volume>\$DedupRecycle\<task_id>\<relative>`, and resolves collisions as `_1`, `_2`;
- hard delete removes normal and read-only files, preserves non-read-only attribute bits before removal, and reports `readonly_cleared`;
- missing, in-use, access-denied, reparse, path-denied, rename, and remove failures map to the stable codes;
- one item failure does not stop later valid items;
- a target swapped to a reparse point between initial validation and mutation is rejected.

- [x] **Step 3: Implement minimum safe mutation logic**

For soft mode, construct a same-volume destination, validate every existing
