# M4 Phase-2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build on-demand partition-pHash/Sobel/six-frame computation, dispatch it to the owning Agent, rescreen M3 candidates into confirmed groups, and expose score details in the GUI.

**Architecture:** Portable BLOB and protocol contracts are implemented first, followed by native/cgo computation, the existing Worker/Agent lifecycle, and finally GUI dispatch/rescreen/group/UI vertical slices. Candidate rows are addressed only by normalized content keys; confirmed group replacement preserves exact and M3 candidate kinds.

**Tech Stack:** Go 1.26, msgpack v5, SQLite, pgx v5/PostgreSQL 16, C++17/CMake/MSVC, `mediacore.dll`, ffmpeg/ffprobe, PowerShell verification.

## Global Constraints

- `docs/details/M4-phase2.md` and `docs/superpowers/specs/2026-07-28-m4-phase2-adaptation-design.md` are authoritative.
- SHA-512 is lowercase 128-character `TEXT` outside native algorithm boundaries.
- pHash/Sobel thresholds are T2 `0.80`, per-part Hamming `10`, T3 `0.85`; video T4 `0.80`, six frames, minimum valid/pass count `4`.
- Task shard size is at most `5000`; image/video watchdogs are `30s/120s`; each frame command timeout is `20s`.
- Existing msgpack message numbers and phase-1 fields remain backward compatible.
- Do not touch M3 candidate or exact groups when rebuilding confirmed image/video groups.
- No Git repository exists; replace commit steps with exact file reports, independent review, and fresh controller evidence.
- Second independent Windows verification is `USER_WAIVED`; do not attempt it.
