# Rust V2 瞬态计算架构收口

日期：2026-08-30

## 结论

Rust V2 的 Node 计算链已经收口为“当前运行使用进程内状态和按物理盘划分的 TSV，长期结果只保存 SQLite 当前事实”。协议版本固定为 V5。扫描、缓存查询、Worker 计算、同步、性能调度、多机器去重和逐项删除属于主功能；任务恢复、分析恢复、复核/删除历史和过度的文件索引不再属于产品入口。

本文按当前工作树源码和既有验证报告整理。最终回归以主代理实际运行的命令和证据为准；本文不把未运行的真实媒体测试写成通过。

## 1. 保留和删除

| 保留 | 删除/不再使用 |
|---|---|
| Node 当前扫描、基础计算、Worker 崩溃隔离和结果查看 | Node 持久任务、TaskCatalog、任务恢复和阶段恢复 |
| SQLite 内容、位置、特征、outbox 和当前文件事实 | SQLite 新建/更新任务历史、分析运行历史、复核历史、删除批次历史 |
| PostgreSQL 多机器同步、中心当前索引和跨机器分析 | Desktop 消费 Node 本地分析、恢复旧中心分析运行 |
| 按物理盘的 SSD/HDD/Unknown 权重调度和老化保护 | 把读取线程池或 FIFO 当作唯一调度模型 |
| P/C/F 瞬态任务文件和逐项删除确认 | 删除历史、恢复日志和持久删除计划 |
| 最近一次成功 `latest-analysis.result.tsv` | JSON、`.idx`、结果历史和用户可见分页 |
| Worker 事件、路径、CPU、物理盘 IO 和队列遥测 | 以遥测表替代当前任务事实或把旁路错误变成任务失败 |

## 2. 当前数据流

```text
解析根目录/物理盘
        ↓
稳定文件清单
        ↓ 真实批量缓存查询（每批最多 1000）
完整命中 ───────────────┐
                        ├─ SQLite 当前事实 / outbox（按需写）
缺失项 → 物理盘 TSV(P) → Worker → SQLite ACK → TSV(C/F)
        ↓
本次运行完成 → 保存当前扫描快照 → 清理 runtime
        ↓
当前扫描 + library_revision → 本地分析 → 原子发布最新 result.tsv
```

扫描开始前就确定根目录对应的物理盘编号、介质类型和每盘额度。文件列表按物理盘进入 lane，不在列出文件后再用路径猜盘。Everything 是默认枚举器，只有不可用或完整失败时才受控回退 Walker。

缓存阶段只查询，不为每个文件做单独 SELECT。路径键和 MD5/内容键分别使用真实批量查询；完整缓存命中项不写任务文件，空值、默认值、错误长度和失败占位符均不视为完整。插入或更新只发生在计算结果、同步导入、当前文件变化或删除成功确实需要时。

## 3. 瞬态任务和重启

`RuntimeTaskRegistry` 保存当前 Node 的 Task ID、Runtime ID、状态、统计、阶段、Worker 和失败路径。它是进程内 registry，不是 `TaskCatalog`，重启后不存在旧任务列表。

每个物理盘的任务文件是 UTF-8 TSV，每行一个真实待处理文件，状态为 `P`（待处理）、`C`（SQLite 确认完成）或 `F`（失败/跳过）。TSV 只服务当前运行，Node 启动不会扫描旧文件进行恢复；任务、分析和删除结束后清理本次 runtime。重启只重新开始新的计算，不要求恢复旧任务。

Worker 的完成、读取失败和崩溃都必须带 Runtime/项身份和规范路径。Node 在当前 registry、运行 NDJSON 和验收证据中记录这些事件；必要的单文件故障可以作为 SQLite 当前诊断事实保存，但不建立崩溃历史。

## 4. SQLite 和结果文件

SQLite 的新入口只把长期可复用数据作为事实源：

- 内容键、文件大小、媒体类型和当前活动位置；
- 图片/视频基础及二筛特征、媒体元数据和当前文件故障；
- 当前同步 outbox、library revision、同步状态，以及删除后需要同步的文件活动状态。

仓库仍可能物理存在旧 `tasks`、`analysis_runs`、`review_marks`、`delete_batches` 等表和 API。这些是兼容 schema/API，不代表新流程会写入或恢复它们；本次收口不做破坏性删表。新删除路径只更新 `files.active=false` 和 file outbox，不生成新的删除墓碑。

本地分析只接受当前已完成扫描快照和匹配 revision，按 `(ContentKey, LocationKey)` 排序去重并批量查询。只有完整基础特征进入筛选，缺失二筛才创建当前瞬态计算项。分析完成后只原子替换固定的 `latest-analysis.result.tsv`，每行一条结果；`latest-analysis.partial.tsv` 仅为临时发布文件。失败或取消删除 partial，不覆盖上一份成功结果，不生成 JSON 或 `.idx`。

结果查看使用滑动窗口动态加载，新窗口整体替换旧窗口，不追加历史，也不向 UI 暴露游标和分页按钮。复核标记只存在当前进程的内存结果上。

## 5. 调度和性能观测

任务分发器使用配置中的 `ssd_threads_per_disk`、`hdd_threads_per_disk` 和 `unknown_threads_per_disk` 建立每个物理盘的有效权重，并受全局读取额度、Worker 数和 `total_threads` 共同限制。全局席位不足时按权重轮转/deficit 选择；老化保护让长期等待的 HDD 或其他 lane 获得机会，避免饥饿。

Hash 和 Media 在同一调度 epoch 中联合判断真实 slot、token、output credit、盘额度和全局额度。Media refill 不得绕过仍可派发的 Hash；任一项终态后立即补位。这样两块物理盘可以同时有任务，SSD/HDD 的并发比例由配置决定，而不是把示例值 `5:1` 固化在代码中。

Worker 事件、任务路径、PID 启动世代、CPU 增量、文件读写增量、物理盘队列/延迟和各阶段等待时间继续保留在运行遥测中。CPU 高低和磁盘 IO 高低必须通过这些样本分析，不能仅凭 Worker 空闲数判断，也不把读取线程数等同于计算线程池。

## 6. 删除和 Desktop 边界

删除队列同样是当前 runtime 下的 TSV。每一项在删除前重新校验活动位置、大小和 MD5；文件系统操作成功后，先事务更新 SQLite 当前文件事实和 outbox，再将该行标为 `C`。失败/跳过标为 `F` 并继续。删除没有持久计划和历史，启动不恢复旧队列；生产也不做磁盘满自动清理。

Desktop 不读取 Node 本地分析结果。它保留 PostgreSQL 中心同步、中心当前索引和跨机器分析，按事务提交推进同步游标；`start/poll/retry_unresolved` 只服务当前会话，重启不恢复旧 analysis run。Desktop 复核/删除决定保持在内存并向 Node 发送当前项，不写中心历史。

## 7. 单轮真实验收边界

本轮只执行一次完整真实媒体测试，不执行六轮 A/B，也不执行 A-3。媒体根固定为：

- `H:\pik\00000000000`
- `I:\tmp`

枚举器显式使用 Everything；本轮目标配置为 Worker 20、读取线程 12，其他 SSD/HDD 每盘额度从配置文件读取。验收观察两个物理盘是否同时读取、权重和老化保护是否生效，并保存 Worker 终态、崩溃路径、CPU、磁盘 IO、队列和最终结果证据。任务到达明确终态即可结束，不必机械等待 1800 秒。

正式包仍只包含四个顶层 EXE、固定 FFmpeg DLL、许可证、schema/config 和 manifest；测试客户端与 data/runtime 不进入正式包。构建、静态验收和真实运行目录均与 `I:\Tool` 隔离，未有实际证据时不得宣称部署或通过。

## 8. 兼容说明和验证

兼容 schema/API 继续保留是为了旧测试和编译边界，不改变新的事实源。新入口必须能证明：不写旧任务/分析/复核/删除历史；批量查询不是逐项查询；完整缓存命中不进入任务文件；P/C/F 只有在 SQLite 确认后推进；重启清空瞬态运行；结果窗口替换而非分页追加。

代码和行为测试完成后运行 `cargo fmt --all -- --check`、`git diff --check` 及相关定向测试；真实媒体验收另行保存配置、包/源码 SHA、媒体前后清单、运行 NDJSON、系统采样和报告。本文只记录架构收口，不代替这些命令的实际结果。
