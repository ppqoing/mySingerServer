# 节点托盘部署与使用

## 文档范围

`nodetray.exe` 是每台 Windows 媒体节点上的常驻通知区域程序。它通过本机
控制面管理 Agent 和可选的“删除 Helper”，提供交互式配置、状态查看、启动、
受控停止和重启；它不取代中央 GUI，也不直接管理 Worker。

本文说明已实现接口的部署和操作语义，但不据此宣称安装包、代码签名、
WebView2 引导程序打包或真实 Windows 动态验收已经完成。当前动态验收状态见
[节点托盘验收记录模板](../acceptance/node-tray-acceptance.md)。
本次生命周期修复的静态验收证据见
[节点托盘生命周期修复验收记录](../acceptance/node-tray-lifecycle-repair-2026-08-03.md)。

## 角色与权限

| 组件 | 常用权限 | 所有者与职责 |
|---|---|---|
| 节点托盘 | 当前登录用户 | 交互式配置、状态汇总、Agent/Helper 生命周期协调 |
| Agent | 当前登录用户 | 扫描、同步并自动创建和监督 Worker |
| Worker | Agent 子进程 | 执行媒体计算；在托盘中只读 |
| 删除 Helper | 管理员 | 可选的受控删除组件，只在配置允许范围内工作 |

Agent、删除 Helper 和托盘程序应位于同一台机器，并由同一部署账号的交互式
会话管理。Agent 不会自动启动 Helper；是否启用 Helper 由操作员在托盘中明确
选择。

## 部署前检查

管理员应先确认：

- 目标系统为受支持的 Windows x64 交互式用户会话；
- `nodetray.exe`、`agent.exe`、`worker.exe` 及其本地运行依赖来自同一次经验证
  的构建；需要删除功能时才提供 `helper.exe`；
- 程序文件使用只读受保护目录，正式配置和备份使用设计规定的固定数据目录；
- WebView2 Runtime 已安装，或已准备来源、SHA-256、大小和许可证均经过清单
  验证的官方 Evergreen 引导程序；
- 中央服务地址、数据库信息和本机媒体目录由授权管理员提供，且不会写入截图、
  通知、工单或公开日志。

生产布局的逻辑位置固定如下，实际系统根目录由 Windows 已知文件夹 API 解析：

| 内容 | 固定相对位置 |
|---|---|
| 托盘、Agent、Helper 程序 | `Program Files\MySingerServer\` |
| Agent 配置和日志 | `ProgramData\MySingerServer\Node\` |
| Helper 配置和日志 | `ProgramData\MySingerServer\Helper\` |
| 托盘设置 | 当前用户本地应用数据下的 `MySingerServer\NodeTray\` |

程序不会把正式配置或凭据写入 WebView2 用户数据目录。完整 ACL、固定任务和
一次性提权边界见[节点托盘安全说明](node-tray-security.md)。

## 操作员快速开始

1. 从管理员准备的固定程序目录或受信任快捷方式启动 `nodetray.exe`。通知区域
   出现图标后打开节点控制台。
2. 进入“Agent”页签，使用交互式表单填写全部必需字段。点击“测试配置”，
   修正字段级错误，再点击“保存”。正常流程不直接编辑 JSON。
3. 进入“程序设置”页签，为 Agent 选择“手动”或“自动”。需要当前账号每次
   登录后启动托盘时，启用“登录后启动托盘程序”，然后保存程序设置。
4. 返回“Agent”或“总览”，点击“启动 Agent”。等待 Agent 运行，并确认
   Worker 的 `ready / expected` 达到预期。
5. 只有需要删除能力时才进入“删除 Helper”页签，启用 Helper、添加明确且
   窄范围的允许目录、保持默认软删除并关闭硬删除，然后测试和保存配置。

CLI 参数和 JSON 只用于旧节点迁移、开发诊断或无托盘兼容部署，不是操作员的
正常配置入口。迁移完成后应在托盘中重新加载、验证并保存一次。

## 四个页签

### 总览

“总览”显示 Agent、Worker 和删除 Helper 三张状态卡，包括生命周期、PID、
启动方式、运行时间或最近异常。常用 Agent/Helper 操作集中在状态卡中。
Worker 只读；总览没有启动、停止、重启或删除单个 Worker 的入口。

### Agent

“Agent”页签提供：

- Agent 启动、停止和重启；
- 节点、监听、数据目录、数据库、扫描、同步、Worker、缩略图和调优等结构化
  配置控件；
- “测试配置”“保存”“保存并重启 Agent”；
- Worker 数量、PID、Ready 状态、当前任务摘要和最近错误的只读列表。

普通“保存”不会隐式重启运行中的 Agent。“保存并重启 Agent”只有在配置保存
成功后才请求受控重启。数据库敏感字段必须保持脱敏，不应复制到剪贴板诊断、
通知或日志。

### 删除 Helper

“删除 Helper”页签只管理可选删除组件，提供允许目录、拒绝目录、删除模式、
硬删除开关、回收目录、超时和日志目录等交互控件。

- 空 `allowed_roots` 时禁止启动；
- `allowed_roots` 只配置明确、窄范围的本机媒体目录；
- 新配置默认软删除，建议始终关闭硬删除；
- 既有硬删除配置不会被静默改写，保存前必须再次确认风险；
- 手动启动或写入受保护配置时按需显示 UAC；
- 自动模式使用唯一固定、以最高权限运行的登录计划任务，不接受任意任务名、
  可执行文件或参数。

更详细的同机、同账号和目录白名单要求见
[删除 Helper 部署说明](m5-helper.md)。

### 程序设置

“程序设置”页签提供：

- “登录后启动托盘程序”开关；
- Agent 的手动/自动启动方式；
- 删除 Helper 的启用状态及手动/自动启动方式；
- “关闭窗口时隐藏到托盘”；
- 1～3 秒状态刷新间隔和通知级别；
- 打开固定 Agent/Helper 日志目录和配置备份位置。

“登录后启动”只表示当前部署账号进入交互式会话后启动托盘，不是 Windows
服务，也不承诺无人登录时运行。

保存程序设置时按差异执行：普通的刷新间隔、通知级别或窗口设置变化
不会写入登录启动项，也不会弹出 UAC；只有 Helper 启用状态或自动启动
策略变化时才会修改固定计划任务。外部状态已部分改变但后续保存失败时，
界面会重读实际设置，不显示虚假成功。

## 启动模式

### Agent 手动与自动

- **手动**：托盘只读取状态，操作员点击后才启动 Agent。
- **自动**：托盘在当前账号登录并启动后，先验证固定配置和程序身份，再启动
  Agent。

自动模式不形成异常退出后的无限重启循环。Agent 自身退出时，托盘通知操作员
并等待明确处理。

### Helper 手动与自动

- **手动**：操作员点击管理员启动，Windows 显示 UAC；取消授权不会修改配置、
  计划任务或组件状态。
- **自动**：管理员先通过一次性 UAC 安装固定的最高权限登录计划任务；以后由
  同一账号的该固定任务启动 Helper。

发现任务定义漂移、程序身份不符或保护目录异常时，托盘拒绝认领或运行，并要求
重新授权修复，不会迁就未知任务。

## 保存、备份与恢复

托盘只接收结构化字段。保存时由 Go 后端执行与组件一致的严格校验、受限 ACL、
临时文件写入、刷新和原子替换。正式配置旁只保留一份固定后缀 `.last-good` 的
上次可用备份，并继承相同权限。

原子替换后会重新通过正式 loader 读取目标文件并比对本次规范内容。复读失败
返回 `save_verify_failed`，不启动或重启组件。界面显示的运行配置和已保存配置
SHA-256 均来自后端；两者不同时显示“需要重启后生效”。

配置损坏时不会自动覆盖正式文件。操作员应先查看脱敏错误和 `.last-good`
摘要，再明确选择恢复；恢复后仍要完整校验。不要手工修改正式配置或备份，也
不要把它们复制到 WebView2 数据目录、公共共享或工单附件。

## 窗口、退出和停止超时

- 关闭主窗口默认只隐藏到通知区域，不停止 Agent 或 Helper；
- 窗口设置为“不隐藏到托盘”时，点击关闭会打开统一强制退出确认弹窗；
- 托盘菜单和程序设置页的“退出托盘程序”也只打开同一弹窗；
- 取消时不会结束任何进程；确认时只调用一次 `ForceExitAll`；
- 后端先强制结束 Helper，再强制结束 Agent，并等待已记录 Worker PID 退出；
- 所有后台进程确认退出后才授权关闭 UI；任一组件失败时保留 UI，列出失败组件并允许重试；
- 控制状态中的启动时间仅作为协议兼容字段保留，NodeTray 以 Windows Inspector
  返回的创建时间作为权威身份时间；
- 未初始化且没有记录 PID 的组件在强制退出时视为无需终止；
- Worker 快照不可用不代表 Worker 存活。已知 Worker PID 仍逐个等待；快照不可用
  时以 Agent 退出触发 Job Object 的 `KILL_ON_JOB_CLOSE` 作为其 Worker 结束依据；
- 失败列表只显示 `helper`、`agent` 或 `worker:<PID>`，不再显示通用 `workers`。

强制退出仅使用本次运行已记录的 PID，不做进程路径、启动时间或身份的二次核对。
这是个人使用模式的明确取舍。

## WebView2 缺失或初始化失败

节点托盘在 Wails 初始化时实际检查 WebView2 Runtime，不能因为系统版本较新就
假定已经安装。

- 缺失或版本过低时，只能使用发布清单验证过的微软官方引导程序；
- 安装前必须向操作员说明影响并取得确认；
- 操作员取消后不启动或修改 Agent、Helper、计划任务或登录启动项；
- 安装或初始化失败时，记录不含凭据的错误摘要，由管理员修复 Runtime 后重试；
- 文档和源码存在引导逻辑不代表当前发布包已经携带 WebView2 引导程序。

## 常见问题

| 现象 | 处理 |
|---|---|
| 第二次启动只显示已有窗口 | 托盘按当前用户单实例运行，第二个实例只请求显示现有控制台 |
| Agent 显示未认领实例 | 核对控制管道、组件类型、机器身份、PID、程序规范路径和配置指纹；启动时间由 Windows Inspector 判定，不要按进程名强行结束 |
| Agent 长时间处于启动中 | 查看 Worker `ready / expected` 和脱敏异常；Worker 未全部 Ready 时 Agent 不进入正常运行状态 |
| Helper 启动按钮不可用 | 先启用 Helper、填写非空窄范围允许目录并通过配置测试 |
| Helper 手动启动未发生 | 检查 UAC 是否被取消；取消属于安全退出，不应反复自动弹出 |
| Helper 自动模式提示任务漂移 | 重新核对固定任务定义并由管理员明确授权修复 |
| 保存失败 | 修正字段级错误，检查固定目录 ACL；不要绕过界面直接改 JSON |
| WebView2 缺失 | 由管理员提供并验证官方引导程序，确认安装后重新启动托盘 |
| 强制退出后界面仍保留 | 查看弹窗中的失败组件，处理后点击“重试强制退出” |

## 明确不在范围

- 不提供远程多节点管理；
- 不直接管理、删除或单独重启 Worker；
- 不把 Agent、Worker 或托盘改成 Windows 服务；
- 不在无人登录时提供托盘界面；
- 不提供“删除节点”、卸载程序、删除组件文件、清理配置/日志/媒体数据或自动
  更新功能；
- 不扩大 Helper 的删除白名单、用户确认或审计语义；
- 不保证安装包、签名证书或 WebView2 bundle 已随当前源码快照交付。

## 验收边界

静态合同、单元测试和前端构建不能替代真实 Windows 交互验收。UAC、固定计划
任务、当前用户登录启动、HKCU、进程启停、WebView2 缺失模拟以及资源测量都
必须在明确授权的隔离会话中运行。未执行的真实动态项目保持
`BLOCKED_NOT_RUN_DYNAMIC`，不得写成 `PASS`。
